## 一句话设计

把 weekly 重构为 `Industry Claim Ledger`：系统先生成“行业方向主张”，再用完整十轴证据矩阵、反证审计、工具覆盖状态和多 Agent 贡献账本决定它是核心行业趋势、观察中趋势、风向探针、项目热度簇，还是证据不足方向。项目仍是重要证据轴和落地样本，但不再是趋势成立的唯一底座。

用户应该能用一句话理解新版 weekly：

> 先看本周哪些 Agent 行业主张成立，再看证据矩阵为什么支持它，最后看缺口、反证和下周观察点。

## 设计 Thesis

本设计不是“给现有周趋势加更多来源”，而是更换趋势判断的产品原语。

旧原语是：

```text
high-score projects -> tag / paradigm clustering -> weekly trend prose
```

新原语是：

```text
industry evidence events
  -> evidence axes
  -> industry claim ledger
  -> counter-evidence audit
  -> trend tier decision
  -> weekly industry narrative
```

核心判断：

1. 行业趋势是一个可审计主张，不是几个项目共同标签。
2. 每条主张必须在同一张证据矩阵中暴露强轴、弱轴、缺失轴和反证轴。
3. 资本、政策、宣传、新闻可以发现前置信号，但不能单独证明核心行业趋势成立。
4. 多 Agent 分工只负责搜寻、整理、核验和审计，最终等级必须由可机器验证的规则裁决。
5. 工具不可用时，系统必须表达“本周该证据轴未参与或只弱参与”，不得把缺失误写成“没有趋势”。

## 新原语语义冻结

为避免后续 ExecPlan、实现或评审把这条链路误写成几层随意处理，本节冻结每个新原语的产品语义、输入输出和禁止误解。

### `industry evidence events`

- 含义：行业层最小事实单元，对应一个可追溯的方向级证据事件，而不是一句总结、一个搜索结果列表或一段周报 prose。
- canonical contract：`IndustrySignalEvent`
- 输入来源：repo、paper、conference、product release、developer post、community thread、funding、policy、thinktank report、news，以及外部 Agent 产出的结构化结果。
- 输出义务：必须携带 axis、source、actor/target、agent relevance、authority、audit 和可追溯引用。
- 不允许被理解为：任意原始网页片段、Trend Agent 自由发挥的观点句子、还没结构化的搜索结果堆。

### `evidence axes`

- 含义：把 event 按行业判断维度组织成固定十轴证据结构，用来回答“这条方向主张在哪些维度强、弱、缺失、冲突”。
- canonical contract：`AxisEvidenceSummary`
- 输入：围绕同一 claim 归一后的 `IndustrySignalEvent[]`、tool coverage 状态、authority context 和 scoring profile。
- 输出义务：每条 claim 必须完整输出十轴，不得省略缺失轴；轴是判断维度，不只是来源分类。
- 不允许被理解为：来源网站分类、随实现临时增减的标签桶、一个总分拆成十个展示字段。

### `industry claim ledger`

- 含义：针对单条行业方向主张的周级裁决总账本，是 weekly 行业层的 canonical judgment artifact，不是 UI 卡片，也不是一句趋势标题。
- canonical contract：`IndustryClaimLedger`
- 输入：claim、本周窗口内的 axis summaries、merge audit、counter-evidence audit、agent contributions。
- 输出义务：必须同时保留主张本身、证据矩阵、趋势等级、反证、缺口、Agent 贡献和 public-safe 状态。
- 不允许被理解为：项目聚类结果换个名字、一段 weekly 文案背后的隐式判断、只给前端展示的轻量摘要。

### `counter-evidence audit`

- 含义：由独立审计语义产生的反证、冲突和缺口审查，用来证明该趋势不是只保留正向叙事。
- canonical contract：`CounterEvidenceAudit`
- 输入：supporting events、counter events、merge audit、source bias、conflict groups。
- 输出义务：必须给出 severity、blocking 与否、downgrade recommendation、missing axes 和 unresolved questions。
- 不允许被理解为：文案里的风险提示、Trend Agent 顺手做的自审、没有反证时就可省略的可选块。

### `trend tier decision`

- 含义：rules-first 的趋势等级裁决结果，用来把 claim 明确分为 `core_industry_trend`、`observing_industry_trend`、`wind_probe`、`project_heat_cluster`、`insufficient_evidence` 或 `rejected`。
- canonical contract：`IndustryTrendDecision`
- 输入：claim、十轴 summary、counter-evidence audit、Agent relevance gate 和冻结阈值。
- 输出义务：必须给出 tier、reason、leading/supporting/missing/counter axes、confidence。
- 不允许被理解为：一个黑盒总分映射、weekly 排版时再临时决定的展示等级、靠资本/政策/新闻热度直接冲上核心趋势。

### `weekly industry narrative`

- 含义：面向用户的 weekly 行业层叙事与卡片输出，是从 ledger 派生出来的可读消费面，不是新的推理层。
- canonical contract：`WeeklyIndustryTrendSection`
- 输入：`IndustryClaimLedger[]`、tool coverage report、agent contribution report、industry window status。
- 输出义务：只能重组和解释 ledger 中已存在的结论与证据，不得引入新事实或重算趋势等级。
- 不允许被理解为：LLM 最后写一篇行业评论、跳过 ledger 直接从 event 拼周报、前端自己重算后再展示的 narrative。

ExecPlan 编写约束：

- 这条链上的每一个原语都必须落到独立 artifact、schema、模块边界或明确的 stage 输出，不能只在 prose 中出现名字。
- 如果实现阶段重命名模块，可以改实现名，但不能改变这里冻结的语义边界。
- 若某一步暂时无法自动化，必须显式落成 `partial / unavailable / needs_review`，不能把原语直接删掉或并入相邻步骤。

## 范围

### 包含

- 行业级证据对象、证据轴、证据评分和来源分层。
- 完整冻结证据轴：项目/开源、研究/论文、顶会/学术活动、大厂/产品发布、知名开发者/工作室、技术社区/极客讨论、资本/金融、政策/监管、政策研究/智库、新闻/宣传。
- 非 repo 证据进入趋势判断的 canonical contract。
- 可对接外部信息搜寻 Agent / 工具的标准化输入、工具 registry 和四级保障链路。
- 9 个实际 Agent 与 15 个职责项；职责项用于 weekly 覆盖审计，实际 Agent 负责产出和交账。
- 行业主张生成、证据矩阵、反证审计、趋势等级裁决和 weekly 输出结构。
- 行业趋势与项目趋势分区表达。
- 失败、降级、public-safe、审计和测试契约。

### 不包含

- 不重写现有 `ScoreBreakdown.total_score`、项目评分组件或 `discussion_score`。
- 不把外部 Agent 输出直接当作最终趋势结论。
- 不让 weekly 直接读取 provider raw input。
- 不把 AgentRadar 扩张为泛 AI 新闻平台。
- 不引入不可审计的黑盒推荐排序。
- 不创建 ExecPlan，不做代码实现。

## 与现有系统的关系

现有主链路保持：

```text
Signal -> Normalize -> Filter / Scoring -> Action
```

行业趋势层作为 weekly 判断侧车新增：

```text
Project weekly evidence ---------------------------\
External discovery aggregates ----------------------\
Specialized industry evidence packs -----------------> Industry Evidence Normalization
Observer / mission discovery signals ---------------/
                                                       -> Industry Claim Builder
                                                       -> Evidence Axis Scorer
                                                       -> Counter-Evidence Auditor
                                                       -> Trend Tier Decider
                                                       -> Weekly industry output
```

冻结边界：

1. `RawSignal[]` 仍以项目级主源为主，不因行业层新增非 repo 证据而强行扩展。
2. `NormalizedProject` 仍以 canonical repo 为主，不要求 paper、policy、funding、community thread 伪装成项目。
3. 行业层可以读取 `ScoredProject[]`、`WeeklyEvidenceProject[]`、`DailyExternalAggregate[]` 和 observer 产物，但不能反向覆盖项目分数。
4. 如果未来要让行业证据参与项目 score，必须新开 scoring design，同步 `scoring-engine.md`、`config.yaml`、代码和测试；本设计不隐式改造项目评分。
5. `run-weekly` 只能读取已存在的日级行业证据包和 external aggregate 窗口，不直接读取 provider raw input 或调用登录态平台 API。
