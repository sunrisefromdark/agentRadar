# 行业级 Agent 趋势判断：证据轴与相关性门控

> 本文档拆自 [行业级Agent趋势判断设计文档.md](../行业级Agent趋势判断设计文档.md)，是行业级 Agent 趋势判断设计文档包的一部分。

## 冻结证据轴

当前设计采用十个 evidence axes。每条行业主张必须完整输出十轴状态；没有证据也要显式写成 `missing`，不能省略。

| axis_key | 中文名 | 主要证据对象 | 可推动核心趋势 |
| --- | --- | --- | --- |
| `project_open_source` | 项目/开源 | repo、Hugging Face 项目、包生态、benchmark、demo、issue/PR、star/fork/download | 可以，但最多只算一个轴 |
| `research_paper` | 研究/论文 | paper、arXiv、OpenReview、实验室页面、数据集、复现材料 | 可以 |
| `conference_academic` | 顶会/学术活动 | accepted paper、workshop、tutorial、challenge、leaderboard、official schedule | 可以 |
| `product_vendor_release` | 大厂/产品发布 | 官方 blog、release notes、API 文档、开发者大会、客户案例、官方 repo/org | 可以 |
| `developer_studio` | 知名开发者/工作室 | maintainer、工作室、技术意见领袖、GitHub discussion、Substack、talk、podcast transcript | 可以 |
| `community_discussion` | 技术社区/极客讨论 | HN、Reddit 高质量子社区、GitHub Discussions、Hugging Face community、V2EX 高质量讨论、公开论坛 | 可以，但必须可追溯且去重 |
| `capital_finance` | 资本/金融 | 融资、财报、SEC 披露、并购、基金报告、上市公司公告、投资机构报告 | 不能单独推动核心趋势 |
| `policy_regulatory` | 政策/监管 | 政策文件、监管公告、审批、政府项目、标准组织文件、公共采购 | 不能单独推动核心趋势 |
| `policy_research_thinktank` | 政策研究/智库 | OECD.AI、CSET、Stanford AI Index、RAND、Brookings 等报告和研究 | 不能单独推动核心趋势 |
| `news_pr_narrative` | 新闻/宣传 | 官方媒体、行业媒体、叙事扩散、宣传倾斜、可追溯新闻 | 不能单独推动核心趋势 |

中文社区和海外社区不是独立证据轴。它们必须在 `community_discussion`、`developer_studio` 或 `news_pr_narrative` 轴中用 `language`、`region`、`source_type` 和 `authority_tier` 标注，不按语言区域天然加权。

## Agent Relevance Gate

所有行业证据进入主张构建前必须先通过 `Agent relevance gate`。该 gate 用于防止产品漂移成泛 AI 情报平台。

允许进入的主题必须至少命中一个领域关系：

- autonomous action
- tool use
- workflow execution
- agentic coding
- computer use
- browser / web agent
- multi-agent coordination
- memory / long-term context
- eval / governance / safety for agents
- agent runtime / orchestration
- skills / plugins / connectors / MCP
- agent observability / tracing
- permissions / identity / security for agents
- agent UI / workbench / operator handoff
- agentic RL / trajectory learning / self-improvement
- robotics / embodied agents
- research / deep research agents
- enterprise process agents
- vertical agent
- intelligent software automation

其中 `vertical agent`、`intelligent software automation`、`enterprise process agents` 必须明确绑定任务执行、工具调用、环境操作、长期上下文、多步 workflow、人机接管或权限控制中的至少一个 Agent 机制；否则只能判为 `agent_adjacent`、`generic_ai_background` 或 `out_of_scope`，不能仅凭行业场景或自动化叙事进入核心趋势。

判定结果冻结为：

| gate_state | 语义 | 后续处理 |
| --- | --- | --- |
| `agent_core` | 明确属于 Agent / automation / intelligent software | 可参与全部等级判断 |
| `agent_adjacent` | 相邻方向，需要与 Agent 使用场景绑定 | 只能在存在绑定证据时参与 |
| `generic_ai_background` | 泛 AI 背景 | 只能作为背景材料，不进入核心趋势 |
| `out_of_scope` | 无 Agent 关系 | rejected 并保留审计原因 |

`agent_relevance_score` 不采用全主题统一阈值。当前冻结使用 `agent-relevance-profile.v1`：

| relation profile | 适用关系 | auxiliary_min | scoring_min | core_claim_min | 额外要求 |
| --- | --- | ---: | ---: | ---: | --- |
| `direct_agent_capability` | autonomous action、tool use、workflow execution、agentic coding、computer use、browser / web agent、multi-agent coordination、memory / long-term context | 50 | 70 | 70 | 明确描述 Agent 能力、执行环境、工具调用或多步任务。 |
| `agent_infra_runtime` | agent runtime / orchestration、skills / plugins / connectors / MCP、agent observability / tracing、permissions / identity / security for agents、agent UI / workbench / operator handoff | 50 | 70 | 72 | 必须说明其服务于 Agent 执行链路，而不是普通开发工具、监控或权限系统。 |
| `agent_learning_research` | agentic RL / trajectory learning / self-improvement、research / deep research agents、eval / governance / safety for agents | 50 | 68 | 72 | 必须绑定 Agent 行为、轨迹、评测、治理或自动研究流程。 |
| `embodied_vertical_agent` | robotics / embodied agents、vertical agent、enterprise process agents、intelligent software automation | 55 | 75 | 78 | 必须有任务执行、环境操作、工具调用、长期上下文、多步 workflow、人机接管或权限控制证据，不能只凭行业场景或自动化叙事。 |

任何 profile 低于 `auxiliary_min` 的证据不得推动趋势升级；达到 `auxiliary_min` 但低于 `scoring_min` 的证据只能作为辅助背景；达到 `scoring_min` 才可计入轴评分；达到 `core_claim_min` 才能作为核心趋势的 Agent 相关性支撑。

`agent-relevance-profile.v1` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `relation profile` | 枚举 ID | Agent 相关性判断所使用的 profile 名称。 | 每条 `IndustrySignalEvent.agent_relevance` 必须能追溯到唯一 profile；多关系命中时选择最严格的 profile，除非 evidence 明确证明更直接的 Agent 关系。 |
| `适用关系` | 领域关系集合 | 该 profile 覆盖的 Agent 领域关系。 | 只能从 Agent Relevance Gate 的允许主题中映射，不得临时新增未定义关系。 |
| `auxiliary_min` | `0-100` number | 进入辅助背景 / 旁证的最低 Agent 相关性分。 | 低于该值的 evidence 只能进入 rejected 或 generic background，不能推动任何趋势等级。 |
| `scoring_min` | `0-100` number | 允许进入 `AxisEvidenceSummary.axis_score` 的最低相关性分。 | 未达到该值时，不能计入任何 evidence axis 的 `supporting_event_ids`，只能进入说明或缺口。 |
| `core_claim_min` | `0-100` number | 允许作为核心行业趋势 Agent 相关性支撑的最低分。 | 核心趋势至少需要一个支撑事件满足对应 profile 的 `core_claim_min`，否则最高只能为 `observing_industry_trend` 或更低。 |
| `额外要求` | 文本约束 | 除数值外必须满足的机制证据。 | ExecPlan 必须把这些要求落成 reason code 或 validator，不能只比较分数。 |
