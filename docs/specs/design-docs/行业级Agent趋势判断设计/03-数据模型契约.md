# 行业级 Agent 趋势判断：数据模型契约

> 本文档拆自 [行业级Agent趋势判断设计文档.md](../行业级Agent趋势判断设计文档.md)，是行业级 Agent 趋势判断设计文档包的一部分。

## 数据模型

### `IndustrySignalEvent`

`IndustrySignalEvent` 是行业层最小事实单元。它可以来自 repo、paper、policy、funding、community thread、product release 或外部 Agent 输出。

```ts
type IndustryEvidenceAxisKey =
  | "project_open_source"
  | "research_paper"
  | "conference_academic"
  | "product_vendor_release"
  | "developer_studio"
  | "community_discussion"
  | "capital_finance"
  | "policy_regulatory"
  | "policy_research_thinktank"
  | "news_pr_narrative";

type SourceAuthorityTier = "core" | "proven" | "watch" | "ordinary" | "excluded";
type EvidencePolarity = "supporting" | "counter" | "missing_marker" | "context";
type AgentRelevanceState = "agent_core" | "agent_adjacent" | "generic_ai_background" | "out_of_scope";
type ProvisionalAuthorityState =
  | "registry_matched"
  | "provisional_authority"
  | "pending_registry_promotion"
  | "ordinary_unregistered"
  | "rejected";

interface IndustrySignalEvent {
  event_id: string;
  schema_version: "industry-signal-event.v1";
  observed_at: string;
  source_published_at?: string;
  ingested_at: string;
  axis: IndustryEvidenceAxisKey;
  polarity: EvidencePolarity;
  source: {
    source_id: string;
    display_name: string;
    source_url?: string;
    source_type:
      | "repo"
      | "paper"
      | "conference"
      | "product_release"
      | "developer_post"
      | "community_thread"
      | "funding"
      | "financial_filing"
      | "policy"
      | "thinktank_report"
      | "news"
      | "official_pr";
    authority_tier: SourceAuthorityTier;
    language?: "zh" | "en" | "multi" | "unknown";
    region?: string;
    primary_source_distance: "primary" | "near_primary" | "secondary" | "rumor" | "unknown";
  };
  actor?: {
    entity_id?: string;
    display_name: string;
    entity_type:
      | "company"
      | "research_lab"
      | "university"
      | "conference"
      | "developer"
      | "studio"
      | "community"
      | "investor"
      | "regulator"
      | "thinktank"
      | "media";
    authority_tier: SourceAuthorityTier;
  };
  target?: {
    topic_key?: string;
    repo_url?: string;
    paper_url?: string;
    product_url?: string;
    policy_url?: string;
    entity_id?: string;
  };
  agent_relevance: {
    state: AgentRelevanceState;

  };
  authority_review?: ProvisionalAuthorityReview;

```

### 全局字段约定

以下约定适用于本文所有 interface，ExecPlan 不得为同名字段另行解释：

| 字段模式 | 含义 | 执行约束 |
| --- | --- | --- |
| `*_id` | 稳定机器 ID。 | 必须跨同一运行稳定；用于 artifact 之间引用时不得使用展示名、标题或随机 UUID 替代可归一 ID。 |
| `*_ref` / `*_refs` | artifact、source、event、tool 或 registry 的引用。 | 必须能在本次运行产物、registry snapshot 或 source trace 中解析；不可解析时必须进入缺口或 rejected audit。 |
| `reason_code` / `reason_codes` / `missing_reason_codes` / `degradation_reason_codes` | 稳定原因码。 | 必须使用 kebab-case 或 snake_case 的短码，可被测试 fixture 断言；自然语言解释应放入 `summary_cn` 或 notes。 |
| `summary_cn` / `*_summary_cn` / `notes_cn` | 中文可读解释。 | 只能总结结构化字段或引用事实，不得新增未在 event/source/audit 中出现的新事实。 |
| `*_at` | ISO datetime。 | 必须包含时区或采用统一 UTC 存储；展示层再转换为用户时区。 |
| `date` | `YYYY-MM-DD` 运行日期。 | 本设计默认按 Asia/Shanghai 的业务日解释。 |
| `public_safe` | 是否可进入公开 artifact。 | false 的对象不得被 weekly、visual console 或公开 JSON 消费，除非先经过 redaction 并生成新 safe artifact。 |
| `schema_version` | artifact schema 版本。 | breaking change 必须新版本；不得在同一版本下改变字段语义。 |

全局 rule：任何字段如果无法按上述约定生成，必须显式进入 `missing_reason_codes`、`rejected_reasons`、`unavailable_state.reason_code` 或对应 audit，不得静默省略。

`IndustrySignalEvent` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `event_id` | stable string | 行业事实事件的唯一 ID。 | 必须可被 claim、axis summary、audit 反向引用；不得每次运行随机变化。 |
| `observed_at` | ISO datetime | 系统首次观察到该事件的时间。 | 用于 freshness 和运行审计；不能替代来源发布时间。 |
| `source_published_at` | ISO datetime optional | 来源自身发布或更新该事实的时间。 | 有一手来源时间时必须填写；缺失时 freshness 必须降级或标注原因。 |
| `ingested_at` | ISO datetime | 事件进入行业证据包的时间。 | 用于 pipeline 审计，不参与事实新鲜度判断。 |
| `axis` | `IndustryEvidenceAxisKey` | 事件所属证据轴。 | 一个 event 只能有一个主 axis；跨轴证据必须拆成多个 event 并用 dedupe/source chain 关联。 |
| `polarity` | `supporting` / `counter` / `missing_marker` / `context` | 事件相对 claim 的证据方向。 | `counter` 必须进入 `CounterEvidenceAudit`；`context` 不得直接推动升级。 |
| `source` | structured object | 来源本身的信息。 | `authority_tier` 必须按 `SourceAuthorityContextProfile` 解释。 |
| `actor` | structured object optional | 发出、发布或代表该事件的主体。 | 有明确主体时必须填写；没有主体的媒体转载不得伪装成 actor。 |
| `target` | structured object optional | 事件指向的 topic、repo、paper、product、policy 或 entity。 | 至少应提供一个可归一字段；否则只能进入低置信观察或 rejected。 |
| `agent_relevance` | structured object | Agent relevance gate 的结果。 | 必须包含 state、score、matched_reasons，并能映射到 `agent-relevance-profile.v1`。 |
| `authority_review` | `ProvisionalAuthorityReview` optional | 未入 registry 主体的临时权威审查。 | 只有临时权威桥接时填写；不能替代 registry 治理。 |
| `evidence` | structured object | 可公开消费的证据摘要、链接、引用和指标。 | `summary_cn` 必须是归一后的摘要，不得直接复制外部 Agent 自由文本作为事实。 |
| `collected_by_agent_id` | `IndustryAgentId` | 采集该事件的实际 Agent。 | 必须能在 `agent_contributions` 中找到对应贡献项。 |
| `responsibility_id` | `IndustryResponsibilityId` | 采集职责项。 | 必须与该 event 的 axis 匹配；跨职责复用需在 merge audit 中去重。 |
| `tool_route_id` | string optional | 产生该 event 的工具路线。 | 使用工具时必须可追溯到 `ToolRegistryEntry` 或 `AxisToolCoverageReport`。 |
| `audit` | structured object | public-safe、去重和 rejected 审计元数据。 | `public_safe=false` 的 event 不得进入公开 artifact；`dedupe_key` 必填。 |

约束：

- `url` 与 `raw_ref` 至少存在一个。
- `observed_at`、`source_published_at`、`ingested_at` 不得混写。
- `authority_tier="excluded"` 的事件只能进入 rejected / audit，不参与评分。
- `primary_source_distance="rumor"` 的事件只能作为低置信观察或反向检索线索。
- 外部 Agent 的自由文本不能直接写成事实，必须经 adapter 映射到结构化字段。

### `SourceAuthorityContextProfile`

`authority_tier` 不是跨轴通用货币。`core / proven / watch / excluded` 必须在 `axis + source_type + primary_source_distance` 的上下文中解释；同一主体可以在一个证据轴是 `core`，在另一个证据轴只能是 `watch`。

V1 冻结规则：

| evidence axis | 可作为 `core` 的典型来源 | 不得替代的来源 |
| --- | --- | --- |
| `project_open_source` | 官方 repo / org、package registry、benchmark 原始记录、issue / PR 原链、依赖生态原始数据 | star 榜单、媒体项目清单、二手 awesome list |
| `research_paper` | 论文原文、arXiv / OpenReview / proceedings、作者机构页面、数据集 / 复现材料 | 论文解读、社媒摘要、无引用综述 |
| `conference_academic` | 官方 accepted list、proceedings、workshop / challenge / leaderboard / schedule | 媒体榜单、个人观后感、未核验议程截图 |
| `product_vendor_release` | 官方 blog、release notes、API docs、客户案例、官方 repo / org | PR 转述、媒体采访摘要、渠道商宣传 |
| `developer_studio` | 明确身份主体的 GitHub、个人博客、Substack、talk、podcast transcript、repo discussion | 搬运号、二创剪辑、无来源摘要 |
| `community_discussion` | 高质量社区原帖、GitHub Discussions、HN / Reddit 明确 thread、Hugging Face community 原帖 | 平台整体热度、转帖、泛问答或低质量评论区 |
| `capital_finance` | SEC / 财报 / 公司公告 / 投资方确认 / 专业数据库 | 未核验融资新闻、市场传闻、二手估值榜 |
| `policy_regulatory` | 政府、监管、标准组织、公共采购的一手文件 | 新闻解读、智库观点、企业合规宣传 |
| `policy_research_thinktank` | OECD.AI、CSET、Stanford AI Index、RAND、Brookings 等原始报告 | 媒体摘编、政策评论、无来源图表 |
| `news_pr_narrative` | 可追溯一手来源链的新闻、官方媒体、行业媒体、官方 PR | SEO 内容、搬运号、无法追溯来源的宣传 |

趋势升级时，`core / proven` 证据只能在其适配的 evidence axis 内推动升级；不得用一个轴的高权威来源替代另一个轴的一手证据。

`SourceAuthorityContextProfile` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `evidence axis` | `IndustryEvidenceAxisKey` | 该权威上下文适用的证据轴。 | 每个 axis 必须有独立上下文；不得把媒体、社区、政策、金融、论文等来源混用同一权威解释。 |
| `可作为 core 的典型来源` | source type / source pattern list | 在该 axis 中可以被解释为 `authority_tier="core"` 的来源形态。 | 只有同时满足 source type、primary source distance 和 registry tier 的来源，才能作为该 axis 的 core 推动证据。 |
| `不得替代的来源` | source type / source pattern list | 即使来源主体有名，也不能替代该 axis 一手证据的来源形态。 | 这些来源最多作为辅助、观察或反向检索线索；不得被 adapter 提升为该 axis 的 core/proven 一手证据。 |

该 profile 不新增 `authority_tier` 枚举值；它限定现有 `core / proven / watch / excluded` 在不同 axis 中如何解释。实现时必须先确定 `axis` 与 `source_type`，再解释 `authority_tier`，不能先给主体全局权威再套到所有 axis。

### `IndustryEntityRegistryEntry`

Seed Registry 是行业层的可维护事实底座。需求文档中的 V1 Seed Registry 是 V1 完成态覆盖基线，而不是最小可行版本或可被实现阶段继续裁剪的起步清单；设计和落地阶段均不得缩减、抽样实现或改写为少数热门主体。它不是永久闭集，也不能阻断对新兴高价值主体的前沿发现；新增主体只能在完整基线之上扩展，不能作为替代完整基线的理由。

```ts
interface IndustryEntityRegistryEntry {
  entity_id: string;
  display_name: string;
  aliases: string[];
  entity_type:
    | "company"
    | "research_lab"
    | "university"
    | "conference"
    | "developer"
    | "studio"
    | "community"
    | "regulator"
    | "thinktank"
    | "media"
    | "tool";
  authority_tier: SourceAuthorityTier;
  region: string;
  language: "zh" | "en" | "multi" | "unknown";
  source_urls: string[];
  evidence_axes: IndustryEvidenceAxisKey[];
  maintenance_agent_id: IndustryAgentId;
  approval_agent_id: IndustryAgentId;
  access_mode: "public" | "api" | "rss" | "crawler" | "optional_paid" | "human_exception" | "unavailable";
  cost_tier: "free" | "low" | "medium" | "high" | "unknown";
  freshness_expectation: "daily" | "weekly" | "monthly" | "event_driven";
  primary_source_distance: "primary" | "near_primary" | "secondary" | "unknown";
  last_agent_reviewed_at?: string;
  review_status: "active" | "watch" | "needs_review" | "deprecated" | "unavailable";
  human_exception_required: boolean;
  change_reason?: string;
  replacement_entity_ids?: string[];
}
```

`ProvisionalAuthorityReview` 用于处理尚未进入 Seed Registry、但可能代表前沿主体的新兴公司、研究团队、工作室、开发者、会议专题或政策/产业机构。它不能替代 registry 治理，只能作为当周有限权威桥接。

```ts
interface ProvisionalAuthorityReview {
  state: ProvisionalAuthorityState;
  reviewed_by_agent_ids: IndustryAgentId[];
  basis_event_ids: string[];
  basis_summary_cn: string;
  required_registry_action:
    | "none"
    | "create_registry_candidate"
    | "update_existing_entry"
    | "reject_and_keep_watch";
  registry_candidate_ref?: string;
  expires_at?: string;
  limitations_cn: string[];
}
```

`IndustryEntityRegistryEntry` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `entity_id` | stable string | registry 主体唯一 ID。 | 必须稳定、可引用；不得用展示名作为唯一键。 |
| `aliases` | string[] | 主体别名、组织名变体或产品名变体。 | 用于实体归一，不得作为独立主体重复计数。 |
| `entity_type` | enum | 主体类别。 | 必须与证据轴和 source context 一致；例如 regulator 不应被当作 media。 |
| `authority_tier` | `SourceAuthorityTier` | 主体默认权威层级。 | 只是默认值；趋势升级时仍需经过 `SourceAuthorityContextProfile`。 |
| `source_urls` | URL[] | 主体可信入口。 | 至少包含一个可核验入口；空列表不能作为 active entry。 |
| `evidence_axes` | `IndustryEvidenceAxisKey[]` | 该主体可覆盖的证据轴。 | 只能在列出的 axis 中使用其权威；跨轴使用必须更新 registry。 |
| `maintenance_agent_id` | `IndustryAgentId` | 负责巡检该 entry 的 Agent。 | 必须是实际 Agent，不得填职责项或自由文本。 |
| `approval_agent_id` | `IndustryAgentId` | 批准新增、删除、降级的 Agent。 | 不能与 trend-agent 临时判断混同；高影响变更需 audit-agent 参与。 |
| `access_mode` | enum | 该主体主要访问方式。 | 成本、授权或不可用状态必须用该字段表达，不能写进散文。 |
| `review_status` | enum | registry entry 当前维护状态。 | `deprecated/unavailable` entry 不能作为 core/proven 推动证据。 |
| `human_exception_required` | boolean | 是否需要人工例外处理。 | 只能用于争议、授权、法律风险或高影响删除，不得作为常规维护方式。 |

`ProvisionalAuthorityReview` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `state` | `ProvisionalAuthorityState` | 临时权威审查状态。 | 只有 `provisional_authority` 可在当周有限替代一个 core/proven 推动证据。 |
| `reviewed_by_agent_ids` | `IndustryAgentId[]` | 参与审查的 Agent。 | 必须包含 `registry-agent` 和 `audit-agent`；缺任一方不得成为 provisional authority。 |
| `basis_event_ids` | string[] | 支撑临时权威判断的事件。 | 必须是一手或近一手事件，或 core/proven 主体交叉引用事件。 |
| `required_registry_action` | enum | 后续 registry 动作。 | 不能为临时使用后静默消失；必须生成候选、更新或保留 watch 决策。 |
| `registry_candidate_ref` | string optional | registry 候选引用。 | `create_registry_candidate` 时必填。 |
| `expires_at` | ISO datetime optional | 临时权威过期时间。 | `provisional_authority` 必填；过期未入库自动回落。 |
| `limitations_cn` | string[] | 临时权威限制。 | 必须说明不能替代哪些证据轴、门槛或反证审计。 |

冻结规则：

- 新增来源必须写 `change_reason`。
- 删除来源必须写 `change_reason` 与 `replacement_entity_ids`，没有替代时必须写 `unavailable` 原因。
- `human_exception_required=true` 只用于争议项、付费授权项、法律风险项或高影响删除项。
- 高成本或授权受限来源必须用 schema 字段组合表达状态，不得引入未定义状态名：
  - 可选付费来源：`access_mode="optional_paid"`。
  - Agent 异步补证或待审来源：`review_status="needs_review"`，并在 `change_reason` 或后续审核记录中说明原因。
  - 人工授权例外：`access_mode="human_exception"` 且 `human_exception_required=true`。
  - 不可用或未覆盖来源：`access_mode="unavailable"` 或 `review_status="unavailable"`，并写明原因。
- 任何未进 registry 的主体默认最多只能被当作 `ordinary / watch` 处理，不能推动核心趋势升级；唯一例外是通过 `ProvisionalAuthorityReview.state="provisional_authority"`。
- 临时权威必须同时满足：
  1. 由 `registry-agent` 和 `audit-agent` 双方审查，`trend-agent` 不得自授权。
  2. 证据来自一手或近一手来源，或至少被两个独立 `core / proven` registry 主体交叉引用。
  3. `agent_relevance_score` 满足对应 `agent-relevance-profile.v1.core_claim_min`，且不是纯资本、政策、新闻或宣传热度。
  4. 必须生成 `registry_candidate_ref` 或明确 `reject_and_keep_watch`，不能只在当周趋势中临时使用后消失。
  5. 必须设置 `expires_at`；过期前未入库则回落为 `ordinary / watch`。
- 临时权威最多只能替代一条 claim 中的一个 `core / proven` 推动证据，不能替代三轴覆盖、反证审计、Agent relevance gate 或资本/政策/新闻降级规则。

### `ToolRegistryEntry`

每个证据轴必须有四级工具保障链路。

```ts
type ToolAvailabilityState = "ok" | "partial" | "rate_limited" | "failed" | "unavailable" | "not_configured";

interface ToolRegistryEntry {
  tool_id: string;
  tool_name: string;
  covered_axes: IndustryEvidenceAxisKey[];
  route_level: "primary_tool" | "secondary_toolset" | "fallback_tools" | "last_resort_mode";
  access_mode: "local_artifact" | "api" | "mcp" | "rss" | "crawler" | "manual_drop" | "optional_paid";
  cost_tier: "free" | "low" | "medium" | "high" | "unknown";
  rate_limit?: string;
  license_risk: "low" | "medium" | "high" | "unknown";
  freshness_sla: "daily" | "weekly" | "event_driven" | "best_effort";
  failure_mode: string[];
  availability_state: ToolAvailabilityState;
  last_agent_reviewed_at?: string;
  replacement_tool_ids: string[];
  unavailable_state?: {
    reason_code: string;
    since: string;
    affected_axes: IndustryEvidenceAxisKey[];
  };
}
```

`ToolRegistryEntry` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `tool_id` | stable string | 工具 registry 唯一 ID。 | 必须可被 `tool_route_id`、`active_tool_ids`、coverage report 引用。 |
| `covered_axes` | `IndustryEvidenceAxisKey[]` | 工具可覆盖的证据轴。 | 工具只能服务列出的 axis；跨轴使用必须更新 registry。 |
| `route_level` | `primary_tool` / `secondary_toolset` / `fallback_tools` / `last_resort_mode` | 工具在四级保障链路中的层级。 | 不得因为工具可用就自动提升为 primary；primary 必须按 axis 评估。 |
| `access_mode` | enum | 调用或接入方式。 | `manual_drop` 只能作为补录或人工例外，不得成为自动链路默认路线。 |
| `cost_tier` | enum | 调用成本层级。 | `high` 或 `unknown` 不能作为 V1 硬依赖，除非有 fallback。 |
| `license_risk` | enum | 授权、抓取或使用风险。 | `high/unknown` 必须触发降级或人工例外说明。 |
| `freshness_sla` | `daily` / `weekly` / `event_driven` / `best_effort` | 工具理论新鲜度承诺。 | 低于证据轴需求时，只能作为 fallback 或 last resort。 |
| `failure_mode` | string[] | 已知失败模式。 | ExecPlan 必须映射为 reason code，不能只写自然语言。 |
| `availability_state` | `ToolAvailabilityState` | 当前可用状态。 | `partial/rate_limited` 产出的证据必须标记 degraded；`failed/unavailable/not_configured` 不得产出 supporting evidence。 |
| `replacement_tool_ids` | string[] | 替代工具。 | primary 失败时必须优先检查替代工具，再进入 last resort。 |
| `unavailable_state` | object optional | 不可用原因与影响轴。 | `failed/unavailable/not_configured` 时必填。 |

`ToolAvailabilityState` 语义冻结：`ok` 表示可正常用于当前 route；`partial` 表示覆盖不完整但可弱参与；`rate_limited` 表示受限可用且需要降级；`failed` 表示本次运行失败；`unavailable` 表示来源或工具当前不可用；`not_configured` 表示 V1 尚未配置该工具。后三者不得生成 supporting evidence。

### `IndustryClaimBuilder`

`IndustryClaimBuilder` 负责从多源行业证据生成方向级主张。它是 weekly 行业层摆脱旧项目聚类的关键边界，不能被实现为“旧 tag cluster 加证据挂载”。

输入冻结为：

- 最近 7 日 `DailyIndustryEvidencePack[]` 中已通过 `normalization-agent` 的 `IndustrySignalEvent[]`。
- 现有 `WeeklyEvidenceProject[]`，只能作为 `project_open_source` 轴和落地样本输入。
- `DailyExternalAggregate[]` 与 observer / mission discovery summaries，只能先转为 `IndustrySignalEvent` 或 rejected audit 后再参与。
- registry snapshot 与 tool registry snapshot，用于主体权威、来源归属、工具可用性和成本授权判断。

主张生成流程冻结为：

1. 先按 `Agent relevance gate` 排除 `generic_ai_background` 与 `out_of_scope`，保留 rejected reason。
2. 对剩余事件按 `topic_key`、canonical URL / DOI / repo URL / official domain、主体、语义近邻和证据轴聚合为 `claim_candidate_group`。
3. 非 repo 证据可以独立触发 `claim_candidate_group`；不得要求必须存在 repo 或 supporting project。
4. 项目聚类只能触发 `project_heat_cluster_candidate`，除非至少存在一个非项目轴或高权威非 repo 事件与其合并。
5. `trend-agent` 只能在已归一事件和 `audit-agent` 初审结果上生成 `IndustryClaim`，不得临时搜索原始来源补齐 claim。
6. claim 命名必须表达行业方向主张，而不是复用项目标签；`claim_statement_cn` 必须包含方向、适用边界和成立假设。
7. 每个生成的 claim 必须保留 `source_event_ids`、`supporting_event_ids`、`counter_event_ids` 和 `missing_axis_keys`，不得只保留摘要文案。

最低候选生成义务：

- 每个非项目证据轴中达到 `core / proven` 且满足对应 `agent-relevance-profile.v1.scoring_min` 的事件，必须至少尝试进入一个 `claim_candidate_group` 或 rejected audit。
- 每个职责项输出的 accepted events 都必须被 claim builder 统计为 used / rejected / deferred，不得静默丢弃。
- 若 7 日窗口中只有项目轴形成强信号，claim builder 必须生成 `project_heat_cluster` 或 `insufficient_evidence` 候选，而不是把它升级为行业主张。

`IndustryClaimBuilderAudit` 至少包含：

```ts
interface IndustryClaimBuilderAudit {
  candidate_group_id: string;
  input_event_ids: string[];
  used_event_ids: string[];
  rejected_event_ids: string[];
  deferred_event_ids: string[];
  trigger_axis_keys: IndustryEvidenceAxisKey[];
  trigger_reason:
    | "cross_axis_convergence"
    | "high_authority_non_repo_signal"
    | "project_heat_requires_external_confirmation"
    | "counter_evidence_cluster"
    | "manual_observer_seed";
  claim_generation_state: "generated" | "rejected" | "deferred";
  reason_code: string;
  generated_claim_id?: string;
}
```

`IndustryClaimBuilderAudit` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `candidate_group_id` | stable string | 候选聚合组 ID。 | 同一组输入事件在同一运行中必须稳定，便于审计 rejected/deferred。 |
| `input_event_ids` | string[] | 进入候选生成的事件。 | 必须包含所有被考虑事件，不得只记录最终使用事件。 |
| `used_event_ids` | string[] | 被用于生成 claim 的事件。 | 必须是 `input_event_ids` 子集。 |
| `rejected_event_ids` | string[] | 被明确拒绝的事件。 | 每个 rejected event 必须有 `reason_code` 或 rejected audit。 |
| `deferred_event_ids` | string[] | 暂缓处理的事件。 | 必须说明下一步补证或等待条件，不能长期静默。 |
| `trigger_axis_keys` | `IndustryEvidenceAxisKey[]` | 触发候选生成的轴。 | 不能全为空；项目轴单独触发时只能生成项目热度或证据不足候选。 |
| `trigger_reason` | enum | 候选被触发的原因。 | 必须使用枚举值；不能自由文本绕过项目热度限制。 |
| `claim_generation_state` | `generated` / `rejected` / `deferred` | 候选生成结果。 | `generated` 必须有 `generated_claim_id`；`rejected/deferred` 必须有可解释 `reason_code`。 |
| `reason_code` | stable string | 生成、拒绝或暂缓原因。 | 必须可被测试 fixture 断言，不得只写自然语言。 |

防缩水规则：

- 不得用旧 weekly tag / paradigm cluster 直接作为 `IndustryClaim`，除非它通过上述候选生成流程重新生成并留下 audit。
- 不得把单个 Agent 的自由文本主题建议直接写成 claim；必须能追溯到结构化 event。
- 不得因为缺少 repo 而丢弃论文、会议、政策、融资、产品发布、社区讨论或智库报告。
- 不得只输出最终 claim 列表而不保留 candidate audit；否则无法验证哪些行业信号被忽略。

### `AxisEvidenceSummary`

每条 claim 必须对十轴逐一输出 summary。

```ts
interface AxisEvidenceSummary {
  axis: IndustryEvidenceAxisKey;
  status: "strong" | "medium" | "weak" | "missing" | "countered" | "unavailable";
  axis_score: number;
  score_formula_version: "axis-scoring-profile.v1";
  subscore_rubric_version: "axis-subscore-rubric.v1";
  scoring_profile_id: string;
  authority_score: number;
  freshness_score: number;
  independence_score: number;
  primary_source_score: number;
  continuity_score: number;
  agent_relevance_score: number;
  supporting_event_ids: string[];
  counter_event_ids: string[];
  missing_reason_codes: string[];
  leading_entities: string[];
  source_tiers_present: SourceAuthorityTier[];
  tool_route_state: {
    primary_tool_ids: string[];
    secondary_toolset_ids: string[];
    fallback_tool_ids: string[];
    last_resort_tool_ids: string[];
    primary_tool: ToolAvailabilityState;
    secondary_toolset: ToolAvailabilityState;
    fallback_tools: ToolAvailabilityState;
    last_resort_mode: ToolAvailabilityState;
    active_route_level:
      | "primary_tool"
      | "secondary_toolset"
      | "fallback_tools"
      | "last_resort_mode"
      | "none";
    active_tool_ids: string[];
    unavailable_state?: {
      reason_code: string;
      since: string;
      affected_axes: IndustryEvidenceAxisKey[];
    };
  };
  summary_cn: string;
}
```

轴评分不采用全轴统一权重。六个子分是共同审计语言，但每个 evidence axis 必须使用更适合其证据形态的 `AxisScoringProfile`。所有 profile 的权重和为 `1.00`，`axis_score` 的计算公式为：

```text
axis_score =
  weight.authority * authority_score
+ weight.primary_source * primary_source_score
+ weight.independence * independence_score
+ weight.freshness * freshness_score
+ weight.continuity * continuity_score
+ weight.agent_relevance * agent_relevance_score
```

V1 `axis-scoring-profile.v1` 冻结如下：

| axis_key | authority | primary_source | independence | freshness | continuity | agent_relevance | 评分重点 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |

| `product_vendor_release` | 0.24 | 0.23 | 0.13 | 0.17 | 0.13 | 0.10 | 看官方 release、API docs、客户案例、产品迭代和跨厂商呼应，避免把 PR 宣传当作产品落地。 |

| `capital_finance` | 最近 90 日融资、并购、财报、SEC / investor relations 或产业报告可高分；超过 365 日且无后续配置 / 披露时只能作背景。 | 独立披露事件、投资方确认、监管文件、财报段落、并购公告或产业报告；同一融资新闻转载链只算一个来源链。 | SEC / 财报 / 公司公告 / 投资方确认 / 专业数据库可满分；普通科技媒体融资报道不得满分。 | 融资后招聘、并购整合、财报业务倾斜、连续投资或产业研究系列可增强 continuity。 | 资本 authority 只能表达资源投入或关注，不得替代技术成熟、产品落地或核心趋势升级所需交叉证据。 |
| `policy_regulatory` | 最近 180 日政策、监管、标准、公共采购或官方项目可高分；被新政策替代、撤回或过期时必须降级。 | 独立监管机构、标准组织、政府项目、公共采购文件或审批事件；媒体解读不计独立政策来源。 | 政府、监管、标准组织、公共采购一手文件可满分；新闻解读、企业合规宣传不得满分。 | draft -> consultation -> final rule、标准版本推进、采购/项目落地或多机构一致表述可增强 continuity。 | 政策 authority 只能表达监管关注、政策空间或官方动作；不得写成技术成熟或商业落地。 |
| `policy_research_thinktank` | 最近 180 日原始报告、指数、数据集或系列研究可高分；年度报告超过 1 个发布周期无更新时降为背景。 | 独立智库 / 政策研究机构报告、数据附录、指数或系列研究；媒体摘编和无来源图表不计独立单位。 | 原始报告、数据附录、正式研究页面可满分；政策评论和媒体摘编不得满分。 | 同一机构系列追踪、跨机构报告收敛、年度指数持续纳入该方向可增强 continuity。 | 智库 authority 不能替代监管文件或资本披露；只能作为政策研究和叙事判断。 |
| `news_pr_narrative` | 最近 7 日可追溯新闻、官方 PR 或叙事扩散可高分；超过 21 日无独立跟进时不得作为 strong 主因。 | 独立来源链、明确采访对象、官方引用或不同媒体的一手确认；转载链、SEO 内容和通稿群发只算一条。 | 可追溯一手来源链的新闻、官方媒体、行业媒体或官方 PR 可高分；无法追溯来源的宣传不得满分。 | 多日、多地区或多独立来源持续跟进可增强 continuity，但仍只能辅助解释或观察。 | 新闻 authority 不得替代任何技术、产品、政策、资本一手证据；即使 strong 也不能单独推动核心趋势。 |

`axis-subscore-rubric.v1` 执行约束：

- `authority_score` 必须先经过 `SourceAuthorityContextProfile`；同一主体在非适配 axis 中最高只能按 `watch` 或更低处理。
- `primary_source_score` 的上限由 `primary_source_distance` 决定：`primary / near_primary` 可高分，`secondary` 原则上不得超过 60，`rumor / unknown` 不得超过 25，除非进入 rejected / counter audit。
- `independence_score` 必须先应用 `IndustryMergeAudit` 的 source-chain、repeated-actor 和 dedupe 结果；不得以原始材料条数计算。
- `freshness_score` 可以按 axis 曲线细化，但 stale evidence 不能作为核心趋势主导证据，除非有更新来源复核。
- `continuity_score` 必须表示跨时间、跨主体或跨证据链的持续性；单条高权威材料不能自动得到高 continuity。
- `agent_relevance_score` 必须先满足 `agent-relevance-profile.v1` 的 profile 门槛；不允许用其他子分补偿低于 `auxiliary_min` 的 Agent 相关性。

实现可以在 ExecPlan 中细化每个子分的计算方式，但不得删除六个子分，不得让任一 evidence axis 回退到统一权重公式或统一子分 rubric，也不得把轴评分改成材料数量相加。权重或 rubric 如需调整，必须新开 scoring design，版本化为新的 `score_formula_version` 或 `axis-subscore-rubric` 版本，并用 fixture 证明不会产生项目热度吞没、资本/政策/宣传泡沫或泛 AI 漂移。

`AxisEvidenceSummary` 与 `axis-scoring-profile.v1` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `axis` | `IndustryEvidenceAxisKey` | 当前 summary 对应的证据轴。 | 每条 claim 必须恰好输出十个不同 axis。 |
| `status` | `strong` / `medium` / `weak` / `missing` / `countered` / `unavailable` | 该轴在当前 claim 下的证据状态。 | 必须由 axis status profile、反证、缺失和工具状态共同决定，不能只看 `axis_score`。 |
| `axis_score` | `0-100` number | 当前 claim 在该 evidence axis 上的综合证据强度。 | 必须由该 axis 对应的 `axis-scoring-profile.v1` 权重计算，不能人工覆盖或用材料数量替代。 |
| `score_formula_version` | literal string | 计算 `axis_score` 使用的公式版本。 | V1 必须为 `axis-scoring-profile.v1`；未来修改权重必须新增版本，不能复用旧版本名。 |
| `subscore_rubric_version` | literal string | 六个子分使用的每轴计算口径版本。 | V1 必须为 `axis-subscore-rubric.v1`；不得只记录权重版本而隐藏子分口径。 |
| `scoring_profile_id` | `IndustryEvidenceAxisKey` | 当前 axis 使用的评分 profile ID。 | 必须等于 `AxisEvidenceSummary.axis`，例如 `axis="policy_regulatory"` 时 `scoring_profile_id="policy_regulatory"`；不得多个 axis 共用同一个 profile ID。 |
| `authority` | `0-1` weight | `authority_score` 在该 axis 中的权重。 | 只表示权重，不是分数；所有权重列加总必须为 `1.00`。 |
| `primary_source` | `0-1` weight | `primary_source_score` 在该 axis 中的权重。 | 用于强调一手来源距离；不能和 `authority` 合并。 |
| `independence` | `0-1` weight | `independence_score` 在该 axis 中的权重。 | 独立性必须先去重同源转载、同主体多渠道和同作者复述。 |
| `freshness` | `0-1` weight | `freshness_score` 在该 axis 中的权重。 | 不同 axis 的新鲜度时效可在 ExecPlan 细化，但不得删除该子分。 |
| `continuity` | `0-1` weight | `continuity_score` 在该 axis 中的权重。 | 表示跨日、跨周、连续事件或持续采用，不等于来源数量。 |
| `agent_relevance` | `0-1` weight | `agent_relevance_score` 在该 axis 中的权重。 | 该子分必须先通过 `agent-relevance-profile.v1` 门槛检查。 |
| `评分重点` | 文本约束 | 该 axis 评分时最需要防止的误判。 | ExecPlan 必须转成 fixture 或 reason code，不能只作为说明文字忽略。 |
| `supporting_event_ids` | string[] | 支撑该轴评分的事件。 | 只能引用 accepted events；不得包含 context-only 或 rejected event。 |
| `counter_event_ids` | string[] | 该轴反证事件。 | 非空时 status 至少要考虑 `countered` 或降级。 |
| `missing_reason_codes` | string[] | 该轴缺失原因。 | `missing/unavailable/weak` 且缺关键证据时不能为空。 |
| `leading_entities` | string[] | 该轴主要主体。 | 必须来自 registry/provisional authority 或已归一 actor，不得自由写名称。 |
| `source_tiers_present` | `SourceAuthorityTier[]` | 该轴出现过的来源层级。 | 只能反映实际 supporting/counter events，不得为了展示补 tier。 |
| `tool_route_state` | structured object | 该轴使用的工具路线状态。 | 必须与 `AxisToolCoverageReport` 对齐；前端不得重新推导。 |
| `summary_cn` | string | 该轴用户可读摘要。 | 只能总结结构化字段，不得新增未追溯事实。 |

轴状态阈值同样不得全轴统一。V1 `axis-status-threshold-profile.v1` 冻结如下：

| axis_key | strong_min | medium_min | early_signal_min | project_heat_min | core_upgrade_role | 阈值口径 |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| `project_open_source` | 70 | 58 | 50 | 65 | `landing_support` | 开源强度必须体现持续使用、依赖、benchmark 或维护活跃，不只看 star。 |
| `research_paper` | 68 | 56 | 48 | n/a | `technical_support` | 研究轴可较早形成技术方向信号，但核心升级仍需一手论文和权威主体。 |
| `conference_academic` | 66 | 55 | 48 | n/a | `technical_support` | 顶会 / workshop / benchmark 的官方材料比社区转述更快进入 medium。 |
| `product_vendor_release` | 68 | 56 | 48 | n/a | `landing_support` | 产品轴需要官方发布、文档或客户案例，单篇 PR 不应快速到 strong。 |
| `developer_studio` | 66 | 55 | 48 | n/a | `builder_support` | 开发者/工作室轴依赖明确身份与长期 track record，单次爆红最多早期信号。 |
| `community_discussion` | 64 | 54 | 47 | n/a | `adoption_support` | 社区轴更重视独立讨论和持续复现；平台热度不能直接等价 medium。 |
| `capital_finance` | 72 | 60 | 52 | n/a | `attention_signal` | 资本轴阈值更高，默认只能作为投入/关注信号，不能单独支撑核心趋势。 |
| `policy_regulatory` | 74 | 62 | 54 | n/a | `attention_signal` | 政策轴必须有一手监管/标准/采购文件，媒体解读不得达到 medium。 |
| `policy_research_thinktank` | 70 | 58 | 52 | n/a | `attention_signal` | 智库轴需要原始报告或连续研究，单篇评论不能快速升级。 |
| `news_pr_narrative` | 75 | 64 | 55 | n/a | `narrative_signal` | 新闻/宣传轴噪声最高，即使 strong 也只能辅助解释或进入观察。 |

`AxisEvidenceSummary.status` 必须由对应 axis 的 threshold profile 计算。`strong / medium / weak` 不是全局固定分段；`core_upgrade_role` 用于趋势等级裁决，防止资本、政策、新闻或宣传轴把前置信号误写成已落地趋势。

`axis-status-threshold-profile.v1` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `axis_key` | `IndustryEvidenceAxisKey` | 阈值 profile 对应的证据轴。 | 必须覆盖十个 evidence axis；缺失任何 axis 都是结构错误。 |
| `strong_min` | `0-100` number | 该 axis 被判为 `status="strong"` 的最低 `axis_score`。 | `axis_score >= strong_min` 时可判为 `strong`，但仍受反证、工具降级和缺失状态约束。 |
| `medium_min` | `0-100` number | 该 axis 被判为 `status="medium"` 的最低 `axis_score`。 | `medium_min <= axis_score < strong_min` 时可判为 `medium`；低于 `medium_min` 不能算核心趋势所需的 medium 轴。 |
| `early_signal_min` | `0-100` number | 该 axis 可作为早期方向信号的最低分。 | 只用于 `wind_probe`、观察或补证触发；达到它不等于可进入核心趋势。 |
| `project_heat_min` | `0-100` number 或 `n/a` | 开源项目热度簇的专用门槛。 | 仅 `project_open_source` 可为数字；其他 axis 必须为 `n/a`，不得用它生成项目热度簇。 |
| `core_upgrade_role` | `technical_support` / `landing_support` / `builder_support` / `adoption_support` / `attention_signal` / `narrative_signal` | 该 axis 在核心趋势升级中的角色。 | `attention_signal` 和 `narrative_signal` 不能单独推动核心趋势；必须与 technical、landing、builder 或 adoption 类证据交叉确认。 |
| `阈值口径` | 文本约束 | 该 axis 的状态判定注意事项。 | ExecPlan 必须转成测试 fixture 或 reason code，防止只按数字跳级。 |

### `IndustryClaimLedger`

```ts
interface IndustryTrendDecision {
  decision_tier:
    | "core_industry_trend"
    | "observing_industry_trend"
    | "wind_probe"
    | "project_heat_cluster"
    | "insufficient_evidence"
    | "rejected";
  decision_reason_cn: string;
  leading_axes: IndustryEvidenceAxisKey[];
  supporting_axes: IndustryEvidenceAxisKey[];
  missing_axes: IndustryEvidenceAxisKey[];
  counter_axes: IndustryEvidenceAxisKey[];
  confidence: "high" | "medium" | "low";
  not_complete_unless?: string[];
}

interface IndustryClaimLedger {
  ledger_id: string;
  schema_version: "industry-claim-ledger.v1";
  window_start: string;
  window_end: string;
  claim: IndustryClaim;
  claim_builder_audits: IndustryClaimBuilderAudit[];
  axis_summaries: AxisEvidenceSummary[];
  decision: IndustryTrendDecision;
  agent_contributions: IndustryAgentContribution[];
  merge_audit: IndustryMergeAudit;
  counter_evidence_audit: CounterEvidenceAudit;
  public_safe: boolean;
}
```

`IndustryTrendDecision` 与 `IndustryClaimLedger` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `decision_tier` | enum | claim 的最终趋势等级。 | 只能由“趋势等级裁决”规则生成，不能由文案或排序分数直接决定。 |
| `decision_reason_cn` | string | 等级裁决理由。 | 必须引用 leading/supporting/missing/counter axes，不得只写概括判断。 |
| `leading_axes` | `IndustryEvidenceAxisKey[]` | 主要推动等级裁决的轴。 | 只能包含达到对应 status profile 门槛且未被强反证阻断的轴。 |
| `supporting_axes` | `IndustryEvidenceAxisKey[]` | 辅助支撑轴。 | 不能替代 leading axes；attention/narrative 轴默认只能 supporting，除非规则允许 wind probe。 |
| `missing_axes` | `IndustryEvidenceAxisKey[]` | 缺失或不可用轴。 | 必须与 `AxisEvidenceSummary.status=missing/unavailable` 对齐。 |
| `counter_axes` | `IndustryEvidenceAxisKey[]` | 存在反证或冲突的轴。 | 必须与 `CounterEvidenceAudit.counter_event_ids/conflict_groups` 对齐。 |
| `confidence` | `high` / `medium` / `low` | 裁决置信度。 | `high` 需要多轴 strong/medium、core/proven 支撑、无 unresolved strong conflict；存在工具降级或关键缺口时最高 `medium`。 |
| `not_complete_unless` | string[] optional | 完成态缺口条件。 | 用于说明进入更高等级仍缺什么；不能替代 `missing_axes`。 |
| `ledger_id` | stable string | 单条 claim ledger 唯一 ID。 | 必须可追溯到窗口、claim 和 schema version。 |
| `window_start/window_end` | date / datetime | 周级判断窗口。 | 所有 included event 必须可解释为何落入或影响该窗口。 |
| `public_safe` | boolean | ledger 是否可公开消费。 | false 时不得进入公开 weekly 或 visual console。 |
