# 行业级 Agent 趋势判断：运行输出与安全

> 本文档拆自 [行业级Agent趋势判断设计文档.md](../行业级Agent趋势判断设计文档.md)，是行业级 Agent 趋势判断设计文档包的一部分。

## 日级与周级运行口径

### Daily

Daily 可以生成行业证据包，但不做最终行业趋势裁决。

```text
specialized agents / tools
  -> IndustrySignalEvent[]
  -> normalization-agent
  -> DailyIndustryEvidencePack
  -> run-summary / verify audit
```

`DailyIndustryEvidencePack` 采用轻索引产物形态：daily pack 负责冻结当日可消费证据窗口、lineage 引用、公开投影状态和覆盖摘要，不再内嵌全量 accepted / rejected event。全量事件仍以 `normalization-result`、event batch、message envelope 和 artifact manifest 作为 canonical source。

```ts
interface DailyIndustryEvidencePack {
  schema_version: "daily-industry-evidence-pack.v2";
  date: string;
  generated_at: string;
  run_id: string;
  window_start: string;
  window_end: string;
  source_message_ids: string[];
  input_artifact_refs: string[];
  normalized_event_batch_ref: string;
  rejected_event_batch_ref: string;
  agent_contributions: IndustryAgentContribution[];
  accepted_event_count: number;
  rejected_event_count: number;
  registry_snapshot_ref: string;
  tool_registry_snapshot_ref: string;
  public_projection: {
    visibility_tier: "internal_only" | "redacted_public" | "public";
    public_projection_artifact_ref?: string;
    redaction_policy_version?: string;
    contains_raw_text: boolean;
    contains_profile_urls: boolean;
    blocked_reason_codes: string[];
  };
  cost_and_degradation_summary: {
    axis_fallback_count: number;
    budget_exceeded_axis_count: number;
    failed_axis_count: number;
    review_backlog_p1_or_higher: number;
  };
  coverage_summary: Record<IndustryEvidenceAxisKey, {
    status: "covered" | "partial" | "missing" | "failed" | "unavailable";
    accepted_event_count: number;
    counter_event_count: number;
    missing_reason_codes: string[];
  }>;
}
```

`DailyIndustryEvidencePack` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `date` | `YYYY-MM-DD` | daily evidence pack 所属日期。 | 必须按 Asia/Shanghai 运行日解释，不能混用 UTC 日期。 |
| `generated_at` | ISO datetime | 证据包生成时间。 | 用于审计，不得替代事件发布时间。 |
| `run_id` / `window_start` / `window_end` | string | 当次 daily run 和窗口边界。 | 必须能唯一反查 message lineage；window 不得隐式推断。 |
| `source_message_ids` / `input_artifact_refs` | string[] | daily pack 直接消费的消息和 artifact。 | 缺任一关键 lineage ref 时，该 pack 不可被 weekly 消费。 |
| `normalized_event_batch_ref` / `rejected_event_batch_ref` | string | accepted / rejected event batch 的 canonical ref。 | daily pack 不再复制保存全量 event；下游必须通过 ref 下钻。 |
| `agent_contributions` | `IndustryAgentContribution[]` | 当日各职责项贡献账本。 | 必须覆盖 15 个职责项。 |
| `accepted_event_count` / `rejected_event_count` | number | 当日 accepted / rejected 事件数。 | 必须与 batch ref 中 event 数一致。 |
| `registry_snapshot_ref` / `tool_registry_snapshot_ref` | string | 当日使用的 registry 快照。 | weekly 合并时必须记录快照差异或 stale 状态。 |
| `public_projection` | object | daily pack 的公开投影状态。 | `visibility_tier="public"` 时必须存在 `public_projection_artifact_ref`；`internal_only` 时 weekly 只能消费 internal artifact，不得把 blocked 内容直接外显。 |
| `cost_and_degradation_summary` | object | 当日成本和降级摘要。 | 不能只记录成功轴；预算超限、fallback、失败和人工积压都必须显式输出；其中 review backlog 统一记为 `review_backlog_p1_or_higher`。 |
| `coverage_summary[axis].status` | `covered` / `partial` / `missing` / `failed` / `unavailable` | 当日该轴覆盖状态。 | `covered` 不等于 strong；只表示该轴有可用采集覆盖。 |
| `accepted_event_count` / `counter_event_count` | number | 当日该轴 accepted / counter 数。 | 必须与 `normalized_event_batch_ref` 中对应 axis 的计数一致。 |
| `missing_reason_codes` | string[] | 缺失原因。 | `partial/missing/failed/unavailable` 时不能为空。 |

执行补充：

- daily pack 是消费索引，不是 event 仓库；不得把 accepted / rejected 全量事件再次嵌入 pack。
- `source_message_ids`、`input_artifact_refs`、batch refs 必须足以还原 `task_request -> evidence_batch -> normalization_result` 的主链；否则该 pack 只能标记 `failed`。
- `public_projection.blocked_reason_codes` 不能为空，当 `visibility_tier!="public"` 且存在公开阻断时必须显式说明阻断原因。
- `cost_and_degradation_summary` 必须与 `coverage_summary` 对齐；如果某轴因预算超限、fallback 或人工积压降级，daily pack 里必须可见。

### Weekly

Weekly 读取最近 7 日 `DailyIndustryEvidencePack[]`、当前窗口对应的 `RollingEvidenceWindowSnapshot`、现有 project weekly artifacts，以及已先转为 `IndustrySignalEvent` 或 rejected audit 的 external aggregate / observer summaries，再做行业主张裁决。

```text
DailyIndustryEvidencePack[7d]
  + RollingEvidenceWindowSnapshot
  + normalized external aggregate / observer summaries
  + WeeklyEvidenceProject[]
  -> IndustryClaimLedger[]
  -> Weekly industry output
```

规则：

1. weekly 不直接读取 provider raw input。
2. 超过最近 7 日窗口的历史 supporting evidence，只能通过 `RollingEvidenceWindowSnapshot` 进入当前 weekly；不得直接回读旧 raw input、旧消息流或任意历史临时产物。
3. daily industry pack 缺失不阻断主 weekly，但必须至少在 `evidence_window_status` 和聚合 `industry_window_status` 中标注 `partial / missing`。
4. `RollingEvidenceWindowSnapshot` 只提供仍在 freshness / continuity 窗口内的可继承历史证据，不新增事实，也不允许绕过当前 run 的 audit / review / blocking 规则。
5. 如果行业层完全不可用，weekly 回退到现有项目级趋势判断，并显式写出 `行业证据不足，本周仅提供项目级趋势回退判断`。
6. `run-weekly --dry-run` 只能报告计划读取的 industry pack、rolling snapshot、external aggregate 和 weekly writes，不写入新产物。

## Weekly 输出契约

`WeeklyReport` 后续应新增行业层字段，同时保留现有兼容字段。`WeeklyIndustryTrendSection` 的唯一 canonical contract 与 [03-数据模型契约](03-数据模型契约.md) 保持一致，不允许再维护第二套“卡片 ID 分桶版”定义。它是 internal canonical section，不是 public projection 本身。

本章不再重复维护 `WeeklyIndustryTrendSection`、`IndustryTrendCard`、`PublicWeeklyIndustryProjection` 与 `ConsumerWeeklyIndustryView` 的完整 interface。完整结构定义只以 [03-数据模型契约](03-数据模型契约.md) 为准；本章只说明这些 canonical artifact 在运行输出、安全边界和 consumer 消费时必须满足的语义约束。

本章重点约束的字段组如下：

- `WeeklyIndustryTrendSection`：`evidence_window_status`、`publication_readiness_status`、`governance_load_status`、`industry_window_status`、`run_snapshot`、`display_index`、`lineage_refs`、`run_budget_summary`、`consumer_view_ref`、`public_projection_ref`
- `IndustryTrendCard`：`internal_consumption_state`、`public_consumption_state`、`consumer_readiness_state`、`consumer_display_priority`、`freshness_summary`、`warning_badges`、`source_trace_refs`
- `PublicWeeklyIndustryProjection`：`publication_snapshot_at`、`headline_core_card_ids`、`public_card_projection_refs`、`blocked_reason_codes`
- `ConsumerWeeklyIndustryView`：`view_scope`、`visible_card_ids`、`headline_card_ids`、`watchlist_card_ids`、`needs_review_card_ids`、`ordering_basis`

执行约束补充：

- 若本章出现字段名、状态名或枚举值，其类型、required 性和兼容边界仍以 [03-数据模型契约](03-数据模型契约.md) 为准；本章不得单独扩展或缩减 schema。
- 本章可以补充 consumer-facing 语义、阻断规则和显示约束，但不得再形成第二份完整 interface、JSON Schema 或前端自定义 contract。

`WeeklyIndustryTrendSection` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `window_start` / `window_end` | date / datetime | 本次行业周窗口边界。 | 必须与 claim ledger、daily pack 和 replay window 对齐。 |
| `evidence_window_status.status` | `ok` / `partial` / `missing` / `failed` | 7 日行业证据窗口本身是否足够。 | 只回答证据与 lineage 是否足够，不得混入 public-safe 阻断或治理积压语义。 |
| `usable_day_count` / `missing_day_count` | number | 可用 / 缺失 daily pack 天数。 | 两者加总不得超过窗口天数；异常必须在 notes 中说明。 |
| `recent_3d_usable_day_count` | number | 最近 3 日内可用天数。 | 用于防止“只有周初有数据，周末还写成本周趋势”。 |
| `publication_readiness_status` | object | 当前行业层公开消费是否可放行。 | `blocked` 时不得生成公开行业层；但不自动否定 internal ledger 的 tier 语义。 |
| `governance_load_status` | object | fallback、预算超限、review backlog 等治理负载状态。 | 只能表达运行负载，不得直接改写证据窗口是否存在。 |
| `industry_window_status.status` | `ok` / `partial` / `missing` / `failed` | 面向用户总览的聚合摘要。 | 必须由前三类状态汇总得出；任何真正阻断判断都必须回读具体状态而不是只看这个总值。 |
| `run_snapshot` | object | same-run snapshot 冻结边界。 | 必须固定 fact、claim admission、authority、audit、publication cutoff 和 `review_availability_snapshot`；晚到结果处理与 same-run review 可用性判断都必须服从该 snapshot。 |
| `run_snapshot.fact_partition_snapshot_refs` | string[] | 本次 weekly 实际消费的分区化 fact snapshot refs。 | 必须能证明 headline / admitted claims 读取的是哪些已关闭 partition；不得把尚未关闭的 partition 伪装成已结算。 |
| `industry_summary_cn` | string | 行业层总摘要。 | 不得引入未在 cards / ledgers 中出现的新事实。 |
| `core_industry_trends` / `observing_industry_trends` / `wind_probes` / `project_heat_clusters` / `insufficient_evidence_directions` | `IndustryTrendCard[]` | 五个用户可见分区。 | 卡片必须放入与 `decision_tier` 对应的唯一分区，不得重复出现。 |
| `display_index` | object | readiness / public-safe 视角的二级展示索引。 | 必须与五个 tier 分区使用同一 ledger snapshot；不得由 surface 临时重算。其结构真源仍以 [03-数据模型契约](03-数据模型契约.md) 为准。 |
| `agent_contribution_report` | `IndustryAgentContribution[]` | weekly 汇总 Agent 贡献。 | 必须覆盖 15 个职责项，不能只展示成功项。 |
| `tool_coverage_report` | `AxisToolCoverageReport[]` | weekly 工具覆盖账本。 | 必须覆盖十个 evidence axis，并显式包含来源类型、尝试过的工具、预算状态、accepted/candidate refs 数量和 citation trace 质量。 |
| `lineage_refs` | object | weekly 结果所依赖的关键运行引用。 | 缺少 `claim_candidate_batch_ref`、`audit_result_refs`、`trend_decision_input_ref` 或 `rolling_evidence_snapshot_ref` 时，不得把超过 7 日窗口的历史 supporting evidence 计入当前 weekly。 |
| `run_budget_summary` | object | weekly 预算、fallback、run 级总成本和人工积压摘要。 | 预算与降级必须用户可见，不能只留在 tracing 或日志中；除 axis fallback / backlog 外，还必须显式暴露 `estimated_run_cost_units`、`actual_run_cost_units`、`remaining_run_cost_units`、`run_cost_status` 与 same-run review mode。`review_backlog_p1_or_higher` 必须可由 `HumanReviewQueueItem.review_priority` 与 `queue_state` 反查，active same-run 人审占用则必须可由 `HumanReviewQueueItem.capacity_reservation_refs`、`occupied_slots` 与 `CapacityReservation` 反查。 |
| `ordering_basis` | string[] | 默认排序依据。 | 必须以 `consumer_readiness_state` 和 `consumer_display_priority` 开头；只按 tier 排序视为契约违背。 |
| `consumer_view_ref` | string optional | 面向产品/UI/API 的 consumer projection artifact。 | 存在 consumer-facing weekly 时应填写；consumer 不得直接把 internal canonical section 当成页面 contract。 |
| `public_projection_ref` | string optional | 当前 weekly 对应的公开投影 artifact。 | 存在 public weekly 时必填；缺失时 public consumer 不得从 internal section 自行拼装公开输出。 |

补充冻结：

- 本表只解释 consumer-facing 语义，不重新定义结构真源；字段类型、默认值和兼容边界全部回读 [03-数据模型契约](03-数据模型契约.md)。
- 如果需要新增 weekly/card/projection 字段，必须先修改 [03-数据模型契约](03-数据模型契约.md) 与 `schemas/industry/` 真源，再回到本章补充消费语义；不得先在本章“临时加个字段给前端用”。

`IndustryTrendCard` 字段定义冻结如下：

| 字段 | 类型 / 取值 | 含义 | 执行约束 |
| --- | --- | --- | --- |
| `card_id` | string | 卡片稳定 ID。 | 必须稳定可引用，不得每次渲染重新随机生成。 |
| `claim_id` | string | 对应 `IndustryClaim.claim_id`。 | 必须能反查 `IndustryClaimLedger`。 |
| `claim_ledger_ref` | string | claim ledger 引用。 | 必须能直接下钻到 canonical decision artifact。 |
| `trend_name_cn` / `claim_cn` | string | 用户可读名称和主张。 | 名称不能夸大等级；风向探针必须使用可能性语气。 |
| `decision_tier` | `IndustryTrendDecision.decision_tier` | 卡片等级。 | 必须与所在分区一致。 |
| `decision_confidence` | enum | 对当前 tier 的置信度。 | headline 排序和降级说明必须读取它。 |
| `coverage_audit_state` | enum | 审计/覆盖完成状态。 | 不得被折叠进 `decision_confidence`。 |
| `internal_consumption_state` | `allowed` / `review_required` / `blocked` | internal weekly / internal drilldown 是否可消费。 | 它回答“内部能不能看”；不得由 `public_safe` 或 `consumer_readiness_state` 代替。 |
| `public_consumption_state` | `allowed` / `redaction_required` / `blocked` | public weekly / public projection 是否可消费。 | `redaction_required` 时必须先生成独立 public projection；不得直接公开 internal artifact。 |
| `consumer_readiness_state` / `consumer_display_priority` | enum | surface 消费顺序与优先级。 | public headline、provisional watchlist 和 blocked 分桶必须先读这两个字段。 |
| `decision_reason_cn` | string | 裁决理由。 | 必须与 ledger decision reason 一致或是其摘要。 |
| `evidence_matrix` | `AxisEvidenceSummary[]` | 十轴证据矩阵。 | 必须包含十个 axis，并显式包含每轴的 `axis_applicability_state`；缺失也要显式 `missing/unavailable`。 |
| `leading_axes` / `supporting_axes` / `missing_axes` / `counter_axes` | `IndustryEvidenceAxisKey[]` | 卡片级轴分类。 | 必须与 decision 和 evidence_matrix 对齐；其中 `missing_axes` 只能聚合 `axis_applicability_state="required"` 的缺失轴。 |
| `project_landing_samples` | object[] | 项目落地样本。 | `project_heat_only` 不能被写成行业落地验证。 |
| `freshness_summary` | object | 卡片级 freshness 摘要。 | stale 支撑占主导时必须降级或显式说明；不得把 180 日内旧证据伪装成最近 7 日新趋势。 |
| `warning_badges` | string[] | 稳定缺口与阻断徽标。 | 至少覆盖 `partial_audit`、`low_confidence`、`public_blocked`、`human_review_pending`、`main_pillar_gap`。 |
| `what_to_watch_next_week_cn` | string | 下周观察点。 | 必须来自 missing/counter/early signal，不得凭空新增任务。 |
| `source_trace_refs` | string[] | 下钻追溯引用。 | 必须能追溯到 event、source、agent 或 tool route。 |

状态判定阈值冻结如下：

`evidence_window_status`

- `ok`：`usable_day_count >= 5`，且 `recent_3d_usable_day_count >= 2`，且 `lineage_complete=true`。
- `partial`：`usable_day_count` 为 `3-4`，或 `recent_3d_usable_day_count < 2`，但仍可证明 weekly 读取的是合法 lineage。
- `missing`：`usable_day_count` 为 `1-2`。
- `failed`：关键 lineage ref 缺失、任一 daily pack 的 lineage 元数据非法、超过半数证据轴 `failed/unavailable`，或 claim ledger 无法证明其经过 audit / tier decision。

`publication_readiness_status`

- `ready`：公开 weekly 所需 artifact 全部 public-safe 通过，且无行业层级 public blocking。
- `partial_blocked`：存在部分 claim、card 或 public projection 被阻断，但行业层仍可输出剩余公开内容与明确阻断摘要。
- `blocked`：行业层公开 artifact 无法合法生成，或 public-safe / publication snapshot 问题已经影响整个行业层公开输出。

补充冻结：

- `publication_readiness_status` 只回答 public consumption；不得反推 internal weekly 是否可继续保留 claim ledger。
- 当 `public_consumption_state="redaction_required"` 时，相关 card 应先进入 `blocked_public_output_card_ids` 或等价公开阻断桶；只有独立 public projection 落账后才允许解除。
- 当 `internal_consumption_state="blocked"` 时，相关 card 不得进入任何内部判断表面，即使 `decision_tier` 已存在也只能进入 suppressed / quarantine。
- public consumer 只能读取 `PublicWeeklyIndustryProjection` 或其显式 `public_card_projection_refs`；不得直接消费 `WeeklyIndustryTrendSection.core_industry_trends`、`observing_industry_trends` 或 `display_index` 后自行决定哪些可以公开。
- product/UI/API 默认应读取 `ConsumerWeeklyIndustryView` 或其显式 card projections；只有审计、治理和 replay 工具才直接消费 `WeeklyIndustryTrendSection`。

`governance_load_status`

- `nominal`：`degraded_axis_count <= 2`，且 `budget_exceeded_axis_count <= 1`，且 `review_backlog_p1_or_higher = 0`。
- `stressed`：`degraded_axis_count` 为 `3-4`，或 `axis_fallback_count >= 3`，或 `budget_exceeded_axis_count > 1`，或存在 `review_backlog_p1_or_higher > 0` 但未影响整层饱和，或 `run_budget_summary.run_cost_status in {"near_soft_stop","soft_stop_reached"}`，或当前 run 的 `run_budget_summary.same_run_review_mode="async_only"` 但未影响整层公开阻断。
- `saturated`：fallback、预算超限、run total budget 已触发 hard cap，或 review backlog / reviewer unavailability 已显著影响 headline 候选消费，导致多条高优先级 claim 只能进入 `needs_review`、`blocked_public_output` 或降级投影。

`industry_window_status`

- `ok`：`evidence_window_status=ok`，`publication_readiness_status=ready`，且 `governance_load_status=nominal`。
- `partial`：`evidence_window_status=partial`，或 `publication_readiness_status=partial_blocked`，或 `governance_load_status=stressed`。
- `missing`：`evidence_window_status=missing`。
- `failed`：`evidence_window_status=failed`，或 `publication_readiness_status=blocked` 且公开行业层无法生成。

`IndustryTrendCard.freshness_summary` 执行约束：

- `level="stale_dominant"` 且不存在有效 `freshness_reset_basis_event_ids` 时，该卡最高只能进入 `observing_industry_trends` 或 `insufficient_evidence_directions`。
- `leading_evidence_max_age_days` 必须按 leading evidence 实际 anchor 计算，不得偷换成 run date 或 ingestion date。
- `stale_support_ratio > 0.5` 时，`decision_reason_cn` 必须显式说明“历史延续”而非“本周新形成”。

展示规则：

- 核心行业趋势位于 weekly 主叙事。
- 观察中趋势和风向探针在核心趋势之后。
- 项目热度簇必须与行业趋势分区，不得混在核心趋势卡里。
- 证据不足方向不隐藏，必须进入缺口账本。
- 每张卡必须先按唯一 surface 映射矩阵分配 `display bucket`；显式 `display_index` 与 tier 分区不得出现双重或冲突归属。
- 每张卡的十轴矩阵必须可下钻到 event、source、agent 和 tool route。
- 每张卡必须显式区分“required 但缺失”和“not_material_for_archetype”；不得把后者渲染成用户需要立即补齐的主缺口。
- 每张卡必须展示 freshness 摘要；用户应能区分“本周新增信号”与“历史信号延续”。
- weekly 头部必须同时展示 `evidence_window_status`、`publication_readiness_status`、`governance_load_status` 的摘要，以及聚合 `industry_window_status`、same-run snapshot 边界和 public-safe 阻断摘要；不能把 `partial` 简化成“本周无明显变化”。
- internal weekly 可以保留 `provisional`、`needs_review`、`blocked_public_output` 的 tier 语义；public weekly 只能通过 `PublicWeeklyIndustryProjection` 暴露已准入的那一部分，不得与 internal section 共享同一消费入口。

## 失败、降级与安全

| 失败模式 | 状态 | 处理 |
| --- | --- | --- |
| 某专责 Agent 缺失或未配置 | `agent_contribution.status=unavailable` | 对应轴最高只能为 `unavailable / missing`，不得伪装已覆盖 |
| primary tool 失败但备用可用 | `tool_route_state.active_route_level=secondary_toolset/fallback_tools` | 继续使用备用证据，并标注降级来源 |
| 全部工具链失败 | `axis.status=unavailable` | weekly 显示该轴未参与判断，不得写成无趋势 |
| 关键 lineage ref 缺失 | `lineage_failed` | weekly 最多输出 `partial/missing`，不得生成 `core_industry_trends` |
| registry 缺失或 stale | `registry_status=failed/stale` | 默认不得把该主体当作 `core/proven`；只有存在已落账的 `ProvisionalAuthorityReview.state="provisional_authority"` 时，才允许有限桥接，其余情况阻断核心趋势升级 |
| 外部 Agent 输出 schema 非法 | rejected | 保留 rejected event 和原因，不进入评分 |
| 资本/政策/新闻主导但无落地交叉确认 | downgrade | 最多进入 `wind_probe`，不得进入核心行业趋势 |
| 高权威反证出现 | countered | 降级为观察/证据不足，保留历史证据链 |
| 非 repo 证据无法绑定项目 | direction evidence | 仍可进入方向级主张，不强行绑定 repo |
| stale supporting 证据占主导且无刷新依据 | stale_dominant | 最多进入观察或证据不足，不得写成本周新形成核心趋势 |
| 预算超限或人工复核积压明显 | degraded | 必须先进入 `governance_load_status` 与 `run_budget_summary`，再由聚合状态决定是否影响 `industry_window_status` |
| public-safe 验证失败 | publication blocked | 不得提交受影响的公开 artifact；internal weekly 是否可保留必须看 `internal_consumption_state`；若 internal 仍允许，则相关 claim 必须标 `public_consumption_state="blocked"` 或 `redaction_required`，并优先进入 `publication_readiness_status` / `display_index.blocked_public_output_card_ids` |
| 行业层完全失败 | industry fallback | 主 weekly 继续，以项目级趋势回退，并显示行业证据不足 |

Public-safe 边界：

- 不提交 cookie、session、OAuth、账号配置、平台 API 凭据、私有 diagnostics。
- 不提交 raw social text、profile URL、未脱敏 handle，除非已通过 public-safe fixture 规则。
- `data/raw/industry-intelligence/` 若存在，只能作为 local-only raw input，默认不进入公开历史。
- 公开消费产物必须通过 `public_projection.visibility_tier="public"` 或 `"redacted_public"` 显式声明；不得再用单一 `public_safe=true/false` 代替。
- `public_projection.visibility_tier="redacted_public"` 时，必须同时输出 `public_projection_artifact_ref`、`redaction_policy_version`、`contains_raw_text=false`、`contains_profile_urls=false` 和 `blocked_reason_codes` 中已被处理的原因。
- internal artifact 可以继续服务 weekly/audit，但 public artifact 必须是独立投影，不得直接复用 internal 原文件路径。

artifact 生命周期建议冻结如下：

- `data/raw/industry-intelligence/`：默认 local-only，热存 `14-30` 日；是否延长保留由人工复核或法规要求决定。
- `messages/*.messages.jsonl` 与 `messages/*.artifact-manifest.jsonl`：热存 `30` 日；超过后允许压缩为 `messages/compact/*.lineage-index.json`。凡被 weekly claim ledger 引用过的 lineage 最小字段必须保留到 `540` 日，且不得丢失 `run_id`、`message_id`、`correlation_id`、artifact refs、schema version、visibility 和状态。
- `daily/*.evidence-pack.json` 与 `daily/public/*.public.json`：常规保留 `180` 日，用于 weekly replay、时效回看和降级分析。若某日 pack 中的 event 被后续 claim ledger、audit result 或 freshness reset basis 引用，则其最小 replay bundle 必须压缩保留到 `540` 日。
- `normalized_event_batch`、`rejected_event_batch`、`audit_result`、`registry_review_result` 等被 claim ledger 直接或间接引用的 canonical artifact：允许冷存压缩，但最少保留 `540` 日，以覆盖 `freshness-decay-profile.v1` 中最长的 supporting / revalidation 窗口。
- `weekly/*.claim-ledger.json`、`weekly/*.industry-trend-section.json`、`weekly/public/*.public.json` 与 `weekly/latest.json`：长期保留，作为用户可见历史与审计基线。

`entities.json`、`tools.json`、`daily/*.evidence-pack.json`、`messages/*.messages.jsonl`、`messages/*.artifact-manifest.jsonl`、`weekly/*.claim-ledger.json`、`weekly/*.rolling-evidence-window-snapshot.json` 和 `weekly/*.industry-trend-section.json` 是 canonical artifact。`weekly/public/*.industry-projection.public.json` 是公开消费专用 projection artifact。任何 visual console 或 Web surface 只能读取这些 artifact 或其显式 public projection，不得在前端重新推导趋势等级。
