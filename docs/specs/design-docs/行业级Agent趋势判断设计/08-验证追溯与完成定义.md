## Eval 术语解释

其余治理与验收名词统一以 [术语与审计词汇表](09-术语与审计词汇表.md) 为准；这里仅解释本章直接用来验收的评测词。


- `gold set`：人工冻结的正向基准样本，定义“系统应该识别出来的趋势、等级和证据结构”。它不是训练数据，而是验收基线。
- `negative fixtures`：人工冻结的反例样本，定义“系统不应升级的噪声、宣传、泛 AI 热点、单轴热度或低相关自动化内容”。
- `replay windows`：选定的一组历史时间窗口，用来重跑当时的 daily / weekly 输入并比较当前输出是否漂移。
- `replay result`：对某个 replay window 执行重放后的结果摘要，至少要能说明是否重建成功、和历史 baseline 的差异、误报/漏报、citation 准确性以及轴覆盖是否下降。

这些术语都是治理和验收对象，不是“最好有”的分析材料；没有它们，设计不能证明自己在历史窗口下稳定成立。

`blocking_level` 解释：

- `A`：阻断 `V1 可用` 与 `V1 完成态`；对应 Gate A。
- `B`：阻断 `V1 可用` 与 `V1 完成态`；对应 Gate B。
- `C`：只阻断 `V1 完成态`；对应 Gate C。若 `A/B` 已通过但 `C` 未通过，可进入 `pilot`，不得宣称完成态。

## 防偷懒约束

实现阶段不得用以下路径宣称完成：

1. 只把 AgentReach 或新闻摘要拼进 weekly prose，而不生成 `IndustrySignalEvent`。
2. 只给趋势卡增加“研究 / 产品 / 资本”标签，而不输出十轴评分和缺失轴。
3. 只跑一个综合搜索 Agent，而不输出 9 个实际 Agent 与 15 个职责项的贡献状态。
4. 只实现项目/开源、学术、社区三轴，省略资本、政策、智库、新闻/宣传。
5. 只在文案中说“证据不足”，但没有 `missing_axes`、`reason_codes` 和工具状态。
6. 用普通搜索结果替代学术源、政策源或金融源，并把它们当作同等权威证据。
7. 把 capital / policy / news 热度直接升级为核心行业趋势。
8. 行业层失败时静默回退为旧 weekly，而不显式标注行业证据不足。
9. 把 `audit-agent` 与 `trend-agent` 合并为同一不可区分输出，或让 Trend Agent 直接补采原始来源来绕过归一化与反证审计。
10. 把 Finance Agent 或 Policy Agent 降级成 Trend Agent 的临时搜索步骤、新闻摘要步骤或普通网页检索步骤。
11. 只实现 Agent 流程，不实现用户工作流、下钻、SLO / 成本预算、eval / replay、人工复核和治理审计。
12. 用日志、trace 或框架 dashboard 替代 `HumanReviewQueueItem`、`OverrideAudit`、eval fixture 和 canonical artifact。
13. 只定义统一 message envelope，不定义 payload schema registry、producer / consumer、required refs 和 missing behavior。
14. 让 `trend-agent` 在反证审计前直接输出最终 `claim_ledger`，或把 audit 做成最终文案后的补充说明。
15. 十轴使用了不同权重，但六个子分仍采用同一套全局 freshness / independence / primary-source 映射，或把预印本、录用、benchmark 更新、代码 / 复现发布重新压回统一天数。
16. 只写有 timeout / budget / capacity 维度，不冻结 `task-timeout-profile.v1`、`axis-runtime-budget-profile.v1`、V1 默认数值或用户可见降级语义。
17. 所有 claim archetype 仍按同一套“至少 3 轴 strong / medium”偷懒裁决，未区分研究前沿、产品落地、builder 生态、资本 / 政策注意力和项目热度簇。
18. 把综合搜索 Agent、研究 Agent 或新闻聚合结果直接当作政策、金融、官方产品发布轴的 primary supporting source，而不回到官方 canonical fetch。
19. 以“V1 要完整 seed registry”为由，默认高频扫描全部 seed，导致预算、超时和人工复核容量失真。
20. 在 `DailyIndustryEvidencePack` 里重新内嵌全量 accepted / rejected 事件，绕过 event batch 与 normalization lineage，把 daily pack 做回胖快照。
21. weekly 只输出 `claim_ledger` 或 prose，不输出 `lineage_refs`、`run_budget_summary`、`industry_window_status` 阈值输入或 `freshness_summary`。
22. 公开产物直接复用 internal artifact 路径或 hash，只是额外打一个 `public` 标记，而没有独立 redacted/public projection。
23. 为了节省存储把 messages/manifest 压缩成无法 replay 的摘要，丢掉 `run_id`、`correlation_id`、artifact refs 或 visibility 元数据。
24. 在不同章节分别维护冲突的 `industry_window_status`、review capacity 或 retention 数值，让实现按章节自行挑选规则。
25. 只保留 `180` 日日级包，却允许一年以上的 supporting / revalidation freshness 窗口，导致 replay 和审计断链。

完成定义不再使用单个 all-or-nothing 清单，而改为分层 gate。只有 Gate A 与 Gate B 同时通过，才可宣称“V1 可用”；Gate A、B、C 全部通过，才可宣称“V1 完成态”。

状态声明冻结如下：

| 状态声明 | 最低条件 | 允许对外说法 | 明确禁止 |
| --- | --- | --- | --- |
| `shadow_eval` | 结构链路可跑通，但未满足 eval 最低样本量或通过线 | “已建立内部评测 / shadow eval” | 不得宣称 `pilot`、`V1 可用`、`V1 完成态` |
| `pilot` | Gate A 通过，Gate B 或 Gate C 仍有缺口；或 A/B 通过但 C 未通过 | “已进入受限 pilot / 灰度使用” | 不得宣称 `V1 完成态`；若 Gate B 未通过，不得宣称普遍可用 |
| `V1 可用` | Gate A 与 Gate B 全部通过 | “V1 可用，可生成带降级语义的 weekly” | 不得宣称完整覆盖、完整 registry 或完成态 |
| `V1 完成态` | Gate A、Gate B、Gate C 全部通过 | “V1 完成态 / complete” | 不得再以样本不足、兼容未定义或覆盖未完成作为保留条件 |

Gate A：结论正确性硬门槛

- 每条行业 claim 都有十轴矩阵、趋势等级、正证、反证/缺口、Agent contribution、tool route state 和 source trace refs。
- 所有跨 Agent 消息都有 matching payload schema，claim-builder pass、audit pass、tier-decider pass 的顺序可由 message lineage 验证。
- 十个 evidence axis 同时命中 `axis-scoring-profile.v1`、`axis-subscore-rubric.v1` 与 `freshness-decay-profile.v1`，并有 fixture 防止统一子分口径和统一 freshness 天窗。
- claim builder 为每条 claim 冻结 `claim_archetype`，趋势裁决命中 `claim-archetype-decision-profile.v1`。
- 高权威轴命中 official-first source-class 规则；工具 primary/secondary/fallback 的选择能被 `tool-selection-scorecard.v1` 和 coverage audit 解释。
- `WeeklyIndustryTrendSection.v2` 输出 `lineage_refs`、`run_budget_summary`、`industry_window_status` 阈值结果和 `IndustryTrendCard.freshness_summary`，且这些字段有 fixture 覆盖。
- internal artifact 与 public projection artifact 分离，`visibility_tier`、redaction policy、raw-text/profile-url 标记和公开 ref 可被 schema 与 replay 断言。

Gate B：运行可执行性硬门槛

- 9 个实际 Agent 均拥有单独输入、输出、状态和失败语义，且每个职责项都有唯一负责 Agent；但允许多个 Agent 共享运行单元，只要审计边界仍独立。
- Finance Agent 与 Policy Agent 独立输出可审计证据包，并覆盖本设计冻结的金融/政策复杂度要求。
- `DailyIndustryEvidencePack.v2` 采用轻索引结构，能反查 event batch、message lineage、public projection 和成本/降级摘要，而不是重复保存全量事件。
- 消息与 manifest 的 retention / compaction 仍保留可 replay 的 lineage 最小字段；claim-linked replay bundle 能覆盖最长 freshness / revalidation 窗口。
- 用户工作流、SLO / 成本预算默认数值、eval / replay / gold set、人工复核、覆盖审计和治理面均有可验证 artifact 或 fixture。
- 行业层失败时现有 weekly 仍可生成，并显式表达降级。

Gate C：覆盖完成态门槛

- registry materialize 了需求冻结的 seed families、每个 seed 具备 `monitoring_tier`，多轴主体可选配 `axis_monitoring_overrides`，并能标注高成本 / 授权受限来源状态。
- 所有非空 `AxisToolCoverageReport` 都带有完整的 source-class 和选型审计字段，而不是只留自然语言解释。
- V1 完成态下，完整 registry 与分层扫描并存；默认主动扫描只要求 `core_monitor`，`watchlist` / `cold_archive` 保留 tier、原因和触发入口。
- Eval / replay 通过最低样本量与通过线；若仅满足结构与链路要求而未满足样本量，最多只能宣称 `shadow_eval` 或 `pilot`，不得宣称 `V1 完成态`。

## 开放问题

当前无阻塞性开放问题。

以下属于后续扩展，不进入 V1：

1. 是否把行业证据轴反馈到项目 `ScoreBreakdown`。
2. 是否为行业趋势建立独立 Web 工作台编辑/审批流。

## 设计结论

本设计冻结了行业级 Agent 趋势判断的核心产品机制：

- 用 `IndustryClaimLedger` 建立行业主张账本，而不是继续项目聚类。
- 用十轴证据矩阵表达完整行业证据结构。
- 用五种趋势等级保护用户语义。
- 用 9 个实际 Agent 覆盖 15 个职责项，Finance Agent 与 Policy Agent 作为高复杂度独立 Agent，职责项用于 weekly 覆盖审计。
- 用工具四级保障链路处理成本、授权和失败。
- 用 Agent relevance gate 防止漂移为泛 AI 新闻平台。
- 用生产级产品与治理边界补齐用户工作流、SLO / 成本、eval / replay、人工复核、覆盖审计和控制面，避免设计只停留在 Agent 流程层。
- 用明确失败和降级状态保护现有 weekly 主产物。
