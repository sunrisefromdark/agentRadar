## Eval 术语解释

其余治理与验收名词统一以 [术语与审计词汇表](09-术语与审计词汇表.md) 为准；这里仅解释本章直接用来验收的评测词。


- `gold set`：人工冻结的正向基准样本，定义“系统应该识别出来的趋势、等级和证据结构”。它不是训练数据，而是验收基线。
- `negative fixtures`：人工冻结的反例样本，定义“系统不应升级的噪声、宣传、泛 AI 热点、单轴热度或低相关自动化内容”。
- `replay windows`：选定的一组历史时间窗口，用来重跑当时的 daily / weekly 输入并比较当前输出是否漂移。
- `replay result`：对某个 replay window 执行重放后的结果摘要，至少要能说明是否重建成功、和历史 baseline 的差异、误报/漏报、citation 准确性以及轴覆盖是否下降。

这些术语都是治理和验收对象，不是“最好有”的分析材料；没有它们，设计不能证明自己在历史窗口下稳定成立。

## 测试与验证矩阵

| 验收目标 | 验证内容 | 验证方式 | 通过标准 |
| --- | --- | --- | --- |
| weekly 不再只由高分项目决定 | 核心行业趋势至少包含非 repo 证据轴或明确标注项目热度簇 | 单元测试 + fixture weekly | 只有项目轴强时不得进入核心行业趋势 |
| 十轴证据矩阵可见 | 每条 claim 输出 10 个 `AxisEvidenceSummary` | schema 测试 + snapshot | 缺失轴必须为 `missing / unavailable`，不能省略 |
| 十轴评分 profile 与子分 rubric 不混用 | 每个 `AxisEvidenceSummary` 输出 `score_formula_version`、`subscore_rubric_version` 与 `scoring_profile_id` | schema 测试 + scoring fixture | 十个 evidence axis 必须命中各自 profile 和 `axis-subscore-rubric.v1`，禁止全轴统一权重、统一子分口径或材料数量相加 |
| 差异化裁决 profile 生效 | Agent relevance、axis status、authority context、counter severity fixture | 单元测试 + snapshot | 不能用全局阈值、跨轴 authority、统一反证 severity 替代 profile |
| 非 repo 证据可进入方向判断 | paper / policy / funding / product release fixture 无 repo_url | 集成测试 | 能生成 direction-level `IndustrySignalEvent` 与 claim evidence |
| 趋势等级区分清晰 | 五种 `decision_tier` 门槛 | 单元测试 | 各等级 fixture 命中预期 tier |
| 多 Agent 贡献账本成立 | 9 个实际 Agent 与 15 个职责项均有状态 | schema 测试 | 缺失职责项显示 `unavailable`，不影响主 weekly 生成 |
| 多 Agent 消息协议成立 | `IndustryAgentMessageEnvelope`、`IndustryAgentArtifactManifest`、payload schema registry、交互 DAG fixture | schema 测试 + pipeline fixture | 所有跨 Agent 输入输出都有 envelope、manifest、payload schema、依赖关系和幂等键；kind 与 payload_schema 不匹配时报错；无 envelope / manifest / schema 的 artifact 不得被下游消费 |
| claim / audit / decision 三段式成立 | claim-builder pass、audit pass、tier-decider pass 的 message 和 artifact lineage | pipeline fixture + snapshot | `claim_candidate_batch` 先于 `audit_result`，`claim_ledger` 晚于 `audit_result`；未审计 candidate 不得进入 `core_industry_trend` |
| 中间件不替代核心契约 | schema / connector / DAG / tracing middleware fixture | 结构测试 + pipeline fixture | 使用任一中间件时仍必须产出 canonical message、manifest、event、audit、ledger；不得只依赖框架内部 state |
| 生产级用户工作流成立 | 五段式页面、下钻、缺口、stale、partial、needs_review 状态 | snapshot + UI contract fixture | 用户能从 weekly 进入 source / event / agent / tool / counter evidence 下钻；空结果和降级状态不能被写成无趋势 |
| SLO / 成本 / 降级预算可执行 | freshness、latency、tool cost、manual review、public-safe budget 默认数值 fixture | 单元测试 + run fixture | 超时、超预算、缺失天数、复核积压和 public-safe 失败必须按 V1 默认数值进入状态和用户可见降级 |
| Eval / replay 闭环成立 | gold claims、negative fixtures、replay windows、citation accuracy | eval 命令 + snapshot | 能重建历史 claim ledger；输出 false positive / false negative / citation_trace_accuracy / axis_completeness_rate |
| 人工复核和覆盖可审计 | `HumanReviewQueueItem`、`OverrideAudit` fixture | schema 测试 + audit snapshot | tier、authority、public-safe、registry promotion、claim suppression 的人工变更必须保留 before/after、actor、reason、expiry |
| 治理面对象完整 | registry、tools、agents、runs、schemas、evals control-plane fixture | 结构测试 | 每类治理对象都有状态、负责人或主体、审计记录和 schema version，不得只存在日志中 |
| 关键 Agent 没有被合并 | `finance-agent`、`policy-agent`、`registry-agent`、`normalization-agent`、`audit-agent`、`trend-agent` 均有输入 artifact、输出 artifact 和独立状态 | schema 测试 + pipeline fixture | Finance / Policy 不能由 Trend 临时补证；反证审计和趋势综合不能来自同一不可区分输出；Trend 的 claim-builder pass 与 tier-decider pass 可同属 trend-agent，但必须由 audit result 隔开 |
| 反证与缺口可见 | counter event 和 missing axis fixture | 单元测试 + weekly snapshot | 高权威反证触发降级，缺口进入卡片 |
| 工具失效可降级 | primary / secondary / fallback / last resort fixture | 单元测试 | 备用可用时使用备用，全部失败时 axis=`unavailable` |
| 行业边界不泛化 | generic AI news fixture | 单元测试 | `generic_ai_background` 不能进入核心趋势 |
| 资本/政策/宣传不过度升级 | capital/policy/news 强但落地证据缺失 | 单元测试 | 最多进入 `wind_probe` |
| Registry 不缩水 | V1 seed families materialized | 结构测试 | V1 完成态 registry 覆盖需求冻结族，缺失时报错 |
| Public-safe 守护 | raw text、profile URL、token fixture | 结构测试 | public artifact 验证失败并阻止消费 |
| 兼容现有 weekly | 行业层 missing fixture | 集成测试 | 现有 weekly 能生成，并显示行业证据不足 |

## 防偷懒约束

实现阶段不得用以下路径宣称完成：

1. 只把 AgentReach 或新闻摘要拼进 weekly prose，而不生成 `IndustrySignalEvent`。
2. 只给趋势卡增加“研究 / 产品 / 资本”标签，而不输出十轴评分和缺失轴。
3. 只跑一个综合搜索 Agent，而不输出 9 个实际 Agent 与 15 个职责项的贡献状态。
4. 只实现项目/开源、学术、社区三轴，省略资本、政策、智库、新闻/宣传。
5. 只在文案中说“证据不足”，但没有 `missing_axes`、`reason_codes` 和工具状态。
6. 用普通搜索结果替代学术源、政策源或金融源，并把它们当作同等权威证据。
7. 把 capital / policy / news 热度直接升级为核心行业趋势。
8. 行业层失败时静默回退为旧 weekly，而不显式标注行业证据不足。
9. 把 `audit-agent` 与 `trend-agent` 合并为同一不可区分输出，或让 Trend Agent 直接补采原始来源来绕过归一化与反证审计。
10. 把 Finance Agent 或 Policy Agent 降级成 Trend Agent 的临时搜索步骤、新闻摘要步骤或普通网页检索步骤。
11. 只实现 Agent 流程，不实现用户工作流、下钻、SLO / 成本预算、eval / replay、人工复核和治理审计。
12. 用日志、trace 或框架 dashboard 替代 `HumanReviewQueueItem`、`OverrideAudit`、eval fixture 和 canonical artifact。
13. 只定义统一 message envelope，不定义 payload schema registry、producer / consumer、required refs 和 missing behavior。
14. 让 `trend-agent` 在反证审计前直接输出最终 `claim_ledger`，或把 audit 做成最终文案后的补充说明。
15. 十轴使用了不同权重，但六个子分仍采用同一套全局 freshness / independence / primary-source 映射。
16. 只写有 timeout / budget / capacity 维度，不冻结 V1 默认数值或用户可见降级语义。

完成定义：

- V1 不算完成，除非每条行业 claim 都有十轴矩阵、趋势等级、正证、反证/缺口、Agent contribution、tool route state 和 source trace refs。
- V1 不算完成，除非 9 个实际 Agent 均拥有单独输入、输出、状态和失败语义，且每个职责项都有唯一负责 Agent。
- V1 不算完成，除非所有跨 Agent 消息都有 matching payload schema，且 claim-builder pass、audit pass、tier-decider pass 的顺序可由 message lineage 验证。
- V1 不算完成，除非十个 evidence axis 同时命中 `axis-scoring-profile.v1` 和 `axis-subscore-rubric.v1`，并有 fixture 防止统一子分口径。
- V1 不算完成，除非 Finance Agent 与 Policy Agent 独立输出可审计证据包，并覆盖本设计冻结的金融/政策复杂度要求。
- V1 不算完成，除非 registry materialize 了需求冻结的 seed families，并能标注高成本 / 授权受限来源状态。
- V1 不算完成，除非用户工作流、SLO / 成本预算默认数值、eval / replay / gold set、人工复核、覆盖审计和治理面均有可验证 artifact 或 fixture。
- V1 不算完成，除非行业层失败时现有 weekly 仍可生成，并显式表达降级。

## 开放问题

当前无阻塞性开放问题。

以下属于后续扩展，不进入 V1：

1. 是否把行业证据轴反馈到项目 `ScoreBreakdown`。
2. 是否为行业趋势建立独立 Web 工作台编辑/审批流。
3. 是否接入付费金融、咨询或行业数据库的自动授权流程。
4. 是否引入长期用户画像来调整行业趋势排序。

## 设计结论

本设计冻结了行业级 Agent 趋势判断的核心产品机制：

- 用 `IndustryClaimLedger` 建立行业主张账本，而不是继续项目聚类。
- 用十轴证据矩阵表达完整行业证据结构。
- 用五种趋势等级保护用户语义。
- 用 9 个实际 Agent 覆盖 15 个职责项，Finance Agent 与 Policy Agent 作为高复杂度独立 Agent，职责项用于 weekly 覆盖审计。
- 用工具四级保障链路处理成本、授权和失败。
- 用 Agent relevance gate 防止漂移为泛 AI 新闻平台。
- 用生产级产品与治理边界补齐用户工作流、SLO / 成本、eval / replay、人工复核、覆盖审计和控制面，避免设计只停留在 Agent 流程层。
- 用明确失败和降级状态保护现有 weekly 主产物。
