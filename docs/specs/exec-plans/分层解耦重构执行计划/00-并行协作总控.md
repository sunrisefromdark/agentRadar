# 分层解耦重构并行协作总控

## 用法

本文件用于 6 个解耦重构执行计划并行实施时的协作约束。6 人可以并行，但不能各自自由改公共合同。

执行顺序固定为：

```text
Phase 0 全员并行盘点 -> Phase 1-3 owner 内并行建设 -> Phase 4 排队切换入口 -> Phase 5 统一删旧
```

## 总执行顺序

| 顺序 | 阶段 | 谁执行 | 是否并行 | 进入下一步条件 |
| --- | --- | --- | --- | --- |
| 1 | Phase 0：盘点 | 6 个 owner 全员 | 可以并行 | 每人提交 Phase 0 交付模板，公共合同无未确认改动 |
| 2 | Phase 1：建新入口 | 6 个 owner 各自 | 可以并行 | 新入口存在，旧入口仍默认生效 |
| 3 | Phase 2：迁移基础层 | 6 个 owner 各自 | 可以并行 | 基础层验证通过，未改公共合同 |
| 4 | Phase 3：迁移组件/模块层 | 6 个 owner 各自 | 可以并行 | 新模块可被旧 wrapper 或新入口调用 |
| 5 | Phase 4：切真实入口 | 按排队表逐个 owner | 不并行 | 每次只切一个入口，验证通过后下一个 owner 才能切 |
| 6 | Phase 5：删旧重复 | 统一收口 | 不并行 | 旧引用为 0，相邻 owner 确认，验证通过 |
## 六人 owner 表

| 计划 | 主 owner 目录 | 可新建/改造范围 | 默认不能改 |
| --- | --- | --- | --- |
| 前端样式分层 | `app/styles/**` | CSS tokens、base、layout、components、states、routes | DOM 结构、React props、ViewModel、artifact |
| Web SSR 与静态页面 | `app/visualConsole/**` | shell、route render、SSR components、static page | client hydration 行为、artifact 生成、CLI |
| 前端客户端交互 | `app/client/**`、`app/visualConsole/hydration/**` | hydration、events、route state、React route components | SSR 输出合同、artifact schema、CLI |
| VisualConsole 读取与 ViewModel | `src/visualConsole/**` | artifact read、status、models、mappers、renderers、routes | artifact 生产规则、UI 交互、CLI 写盘 |
| Action 报告输出 | `src/action/**` | daily、weekly、run-summary、verification、project-library report builders | CLI dispatch、VisualConsole ViewModel、Web SSR |
| CLI 与 Runtime 编排 | `src/runtime/**` | cli parse、commands、planning、writers、resume | action 业务规则、UI、报告表达 |

## 公共合同冻结表

以下合同默认冻结。确实要改时，先同步相邻计划并记录到对应 exec-plan。

| 合同 | 影响计划 | 规则 |
| --- | --- | --- |
| CSS class / data attribute / DOM selector | 样式、Web SSR、Client | 不改名；要改必须同时更新 SSR、client、style 盘点表 |
| SSR HTML 基础结构 | Web SSR、Client、样式 | JS 失败时页面仍可读；hydration selector 不失效 |
| Client hydration 行为 | Client、Web SSR | 不把业务判断搬进浏览器端 |
| artifact 字段和路径 | Action、VisualConsole、CLI | 不改字段语义、latest/datest 语义、dry-run 写盘规则 |
| ViewModel 字段 | VisualConsole、Web SSR、Client | UI 只展示结构化事实，不重新计算 score/tier/trend |
| CLI 命令名、参数、exit code | CLI、Action | 默认行为不变；新 runtime 只能单命令接入 |
| 删除旧逻辑 | 全部 | 引用清零、验证通过、相邻 owner 确认后再删 |

## Git 并行协作规则

6 人不要直接在 `main` 上各自提交。每个 owner 使用自己的分支，Phase 0-3 在分支内并行开发，Phase 4 的真实入口切换通过 PR / merge 排队进入主分支。

推荐分支：

```text
refactor/styles-layer
refactor/action-output
refactor/runtime-cli
refactor/visualconsole-viewmodel
refactor/web-ssr
refactor/client-interaction
```

同步远程的时机：

| 时机 | 是否必须同步 `main` | 说明 |
| --- | --- | --- |
| 每天开始工作前 | 建议 | 减少长期分叉冲突 |
| Phase 0-3 普通开发中 | 不必每次 | 继续在自己分支做，不因为别人提交就停工 |
| 准备进入 Phase 4 前 | 必须 | 真实入口切换前要基于最新主分支验证 |
| 准备提 PR / merge 前 | 必须 | 避免把过期合同合进主分支 |
| 公共合同被别人改动 | 必须 | 涉及 selector、artifact、ViewModel、CLI 参数等时要同步确认 |
| 每个 Phase 4 PR 合并后 | 相邻 owner 必须 | 依赖该入口的 owner 先更新再继续切换 |

合并规则：

- Phase 1-3：各分支并行，不要求一个人做完另一个人才开始。
- Phase 4：按“Phase 4 切换执行顺序”一个 PR 一个 PR 合并，每个 PR 只切一个小入口。
- Phase 5：删旧逻辑统一处理，不允许个人分支提前删除公共旧入口。
- `main` 始终保持可运行；失败的 Phase 4 PR 不合并，已合并但失败的入口只回滚该入口。
## Phase 0 交付模板

每个人先只读盘点，提交以下内容后再进入 Phase 1：

```text
负责计划：
负责目录：
准备新建目录：
旧入口/旧导出：
依赖的公共合同：
不能改的公共合同：
第一个可迁移的小入口：
验证命令/验证样本：
需要相邻 owner 确认的点：
```

## Phase 4 切换执行顺序

这个顺序只约束 Phase 4 的真实入口切换，不代表 6 个计划要串行开发。Phase 0-3 仍然可以并行；进入 Phase 4 时，每轮只允许一个 owner 切一个小入口，验证通过后再轮到下一个 owner 切一个小入口。

Phase 4 不允许多人同时大切换。一次只切一个入口，按依赖方向从低风险到真实链路推进。

| 顺序 | owner | 优先切换对象 | 前置确认 | 验证 | 回滚 |
| --- | --- | --- | --- | --- | --- |
| 1 | 前端样式 | 一个不改 class 合同的 CSS 基础层，如 tokens/base/layout import | Web SSR、Client 确认 selector/class 未改名 | route screenshot / web smoke | 指回旧 `app/styles.css` 块 |
| 2 | Action 报告输出 | 一个低风险 report builder，如 run-summary 或 verification builder | CLI 确认调用参数不变；VisualConsole 确认 artifact 字段不变 | action tests / dry-run / artifact semantic check | 指回旧 action 导出 |
| 3 | CLI 与 Runtime | 一个低风险 command dispatch，不改命令名、参数、写盘语义 | Action 确认 builder 可用；VisualConsole 确认 latest/datest 路径不变 | CLI workflow / dry-run negative test | dispatch 指回旧 `src/cli.ts` 分支 |
| 4 | VisualConsole 读取与 ViewModel | 一个 route model，如 overview 或 run-health | Action、CLI 确认 artifact schema、路径、状态语义不变 | visualConsole tests / route model smoke | route model 指回旧 build 路径 |
| 5 | Web SSR 与静态页面 | 一个 SSR route render | VisualConsole 确认 ViewModel 字段稳定；Client 确认 hydration selector 不变 | SSR render / HTML smoke | route wrapper 指回旧 render |
| 6 | 前端客户端交互 | 一个 handler 或一个 React route 内部状态切换 | Web SSR 确认 DOM/data attribute 稳定；样式确认 class 不变 | client tests / Playwright smoke | handler 指回旧 `clientScript.ts` |

切完表中的一个小入口并记录验证结果后，才能进入下一项小入口切换。这里的“下一项”不是“下一个人开始开发”，而是“下一个真实入口开始接管运行路径”。任何一项失败，只回滚该入口，不回滚其他已通过入口。

## 硬规则

- Phase 0 可以全员并行，只读，不改代码。
- Phase 1-3 只在 owner 目录内建设新路径；旧文件只做 wrapper 或单点接入。
- Phase 4 必须排队切换，每次只切一个 route、command、builder、handler 或 CSS 层。
- Phase 5 统一删旧；任何人不得独自删除公共旧逻辑。
- 不引入新框架、新状态库、新构建插件，除非已有 exec-plan 明确批准。
